# Native process snapshots

These small deltas reproduce outputs generated by the current NeverD C API
and NeverC producer `182fd2c5dc`, without waiting for another complete LLVM
build. `manifest.json` records the engine source revision, library hash, exact
source digest and actual publication receipts. Every replay checks the current
engine source digest and the LLVM/Capstone/Unicorn gitlinks before applying a
delta to an authenticated original and checking the complete final SHA-256.
A changed engine requires regeneration. This is OS runtime evidence for those
installed bytes; the normal Windows workflow separately rebuilds the engine.

The first-party Windows originals were built and executed in
[`38413109780`](https://github.com/NeverSight/NeverD/actions/runs/38413109780)
with Clang 22.1.6, native MSVC and the Windows SDK. Their source is
`windows-original.cpp`; no runtime DLLs are bundled. The callback original was
then generated with Clang by replacing both the test main and target together.
Their shared object section authenticated the main location, and NeverD
authenticated both function entries. The new main passes the callback and
integer to its new target. NeverC then replaces that actual compiled target,
using the appended `.ndtext` section and its real runtime-function records.
The original callback controls must return 1 and catch/return 42 before its
hosted replacement can be qualified. The C++ source-adapter cases separately
retain the original `int target(int)` declaration and caller.

Linux originals are the GCC/G++ 13.3.0 fixtures in `../neverc-linux`.
All four source profiles invoke NeverC through the public source API: C++ IR,
C++ native object, C++ hosted DynCode and a C hosted throwing callback with two
noninline frames. Linux also includes nine Clang source exception scenarios.
Normal constructor/destructor effects are expected from the original C++
declaration; foreign cleanup remains outside NeverC's translation subset.

`source-patch-native-images.yml` runs Windows x64/ARM64 and Linux x64/ARM64.
Each job requires the actual native host and independently checks every result
three times: 36 Windows or 66 Linux process observations. It retains decoded
publication receipts, exact image hashes and actual return codes. The deltas
and receipts must not be edited as substitutes for rerunning the installer.
