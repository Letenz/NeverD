# 解释器源码恢复

实验性的解释器特化阶段会从已链接的 x64 函数中消除能够静态解析的派发，同时保留运行时输入、内存效果、分支和循环。它依据指令语义工作，不依赖 handler 特征或某一种保护器的操作码表。

```sh
neverd decompile program --func vm_entry --devirtualize --vm-control=r10 \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize --vm-control=r10 \
  --llvm -o recovered-llvm.c
```

`--vm-control` 选择用于区分解释器上下文的完整通用寄存器。该选项可重复使用，但不会提供任何具体值。例如，可以选择由入口代码初始化的字节码游标。用作计数器的运行时输入必须保持动态。如果不同游标值在汇合时缺少必要的上下文区分，恢复可能停止；引擎不得通过猜测派发目标来弥补。若游标被溢出到栈中，`--vm-control-stack=-16:8` 可选择入口 RSP 减去 16 处的八个字节。此偏移相对于函数入口，而不是调整后的当前栈指针。

C API 为 `neverd/sdk/NeverDCAPIDevirtualize.h` 中的 `neverd_devirtualize_source_v1()`。它使用独立事务，不修改会话的普通反编译缓存。失败时不返回源码，但仍可返回 JSON 诊断。两个返回字符串均使用 `neverd_free_string()` 释放。

## 执行契约

二进制适配器目前接受位于其映射地址的已链接 x64 ELF 和 PE 映像。映射、字节和权限必须保持固定，且不得并发修改。严格的按需提升会沿可达机器码进行；遇到不支持的指令、调用、不透明操作、带内存序要求的访问、未解析控制流或语言级异常处理时，恢复会停止。

只有完整的、由文件提供内容的只读范围，且不存在重叠映射或加载器修正，才能提供映像读取常量。可写表、未解析的重定位和运行时采样快照都不能作为不可变读取的证据。COPY 重定位和不完整的异常元数据会被保守拒绝。

源码恢复域要求普通 ABI 返回：每次外部来源存储的目标范围都必须与入口返回地址槽不相交。这是调用方／环境必须满足的显式前提，也包括由外部整数计算出的地址；缺少栈帧来源信息并不能证明数值地址不相交。由栈帧派生的存储地址必须证明与该槽不相交，返回时还必须恢复原始栈指针。来源信息会跨越溢出存储和控制流汇合保留；丢失仿射表达式不会使地址变成外部指针。目前拒绝栈切换、被调用方额外弹栈返回和基于 RET 的派发。二进制适配器强制使用 x64 小端语义。

此流程生成供分析使用的源码和 IR，不证明重定位、栈展开、异步异常或二进制替换的安全性。patch 模式拒绝该选项，也不宣称支持所有解释器或保护配置。

## 当前限制

依赖输入的字节码地址和解码器状态关联尚不能普遍解析。若派发目标得到证明，可以恢复动态分支或循环；但普通分支的测试覆盖并不能证明支持所有间接解码方案。未解析控制流和预算耗尽都表示失败，不会发布恢复源码或部分替代代码。`unresolved-control` 表示拒绝，而不是成功。原生辅助函数调用、异常／重入边界、可变代码及其他架构仍不属于此初版适配器的执行契约。

## 共享实现

`SpecializationProvider` 提供完整提升后的指令和不可变读取证据。`NeverDInterpreterSpecialization` 复用现有 `SymExec` 语义，对整数及控制操作进行部分求值。二进制适配器负责映射和指令解码，不实现第二套指令求值器。

节点由原生指令游标、指令模式，以及选定控制寄存器和入口栈帧槽中的常量共同标识。其余字节级事实通过交集汇合。传入事实变弱时，会重新求值该节点。因此，程序本身的循环仍保持为循环，不会逐次展开每次观察到的迭代。间接目标表达式的所有叶子必须构成有界、精确的常量集合；解析出的目标会变成残余代码中的显式比较和 CFG 边。

动态操作和普通 load/store 保留在 LowIR 中。只有经过证明的不可变读取才会被替换为常量。标量常量、相对于入口栈帧的仿射指针，以及已证明为常量的栈帧字节可以跨节点传递；其他表达式会被舍弃，而不是无限展开。栈帧内存沿用符号状态已有的保守别名失效规则。通过未知且可能形成别名的指针写入时，会使冲突事实失效。这既不假设栈槽私有，也不会根据未经证明的无别名契约将其消除。

唯一的合成指令标签用于区分克隆的上下文。原始指令边界保留在独立的来源映射中；原始重定位、异常和跳转表证书不会复制到新指令实例上。恢复后的 LowIR 在 HighC/LLVM 路径分流前进入普通 LowIR-to-MedIR 转换，共享寄存器、栈、CFG、SSA 和 ABI 处理。HighC 路径的恢复同样要求 MedIR 验证通过。

节点数、每个地址的上下文数、操作数、节点求值次数和有限目标数的预算共同约束分析。预算耗尽或语义不受支持时，不发布残余函数。控制流图完整与源码成功生成是不同条件；公开 API 会检查两者并分别报告。

## 证据与测试

可选的本地 JSON 报告包含输入摘要、选定的控制项、预算、状态、工作量计数、残余块数、原始指令位置，以及恢复时使用的不可变字节。报告包含输入派生信息，只会写入指定的本地路径。

公开测试使用原创的寄存器线程化派发和栈派发机器，各自包含算术、分支／汇合与运行时循环程序。独立的无符号运算参考实现检查返回值、内存写入、进位／借位结果和输出哨兵。恢复得到的 HighC 和 LLVMC 在 O0/O2 下开启未定义行为陷阱编译，再与该参考实现对照执行。负例覆盖未解析派发、可写派发表、不兼容字节序、异常元数据和预算限制。

专项测试目标见 [testing.md](testing.md)。
