# Windows ドライバーのプリエンプティブスケジューリング

任意の `scheduling` オブジェクトにより、Unicorn、KVM、WHP の x64 Windows ドライバーで決定的な CPU0 プリエンプションを有効にできます。省略時は協調方式とアイドル時のみ進む仮想時間を維持します。両フィールドは正の整数で、積は `uint64_t` に収まる必要があります。空のオブジェクトは下記の既定値を選びます。

```json
{
  "scheduling": {
    "quantum_instructions": 1024,
    "instruction_time_100ns": 1
  }
}
```

`quantum_instructions` はスレッドに許可する機械命令の試行数です。`instruction_time_100ns` は試行ごとの仮想時間であり、ハードウェア速度ではありません。モデル API と命令トランザクションの完了後に切り替えます。イベント境界で残りのクォンタムはリセットしません。選択した設定は `configuration.scheduling` に記録します。

`KeSetPriorityThread` と `KeQueryPriorityThread` は `PASSIVE_LEVEL` で実行時優先度を扱います。設定値は 1..31 で、以前の値を返します。0 は予約済みです。この決定的プロファイルでは各スレッドの初期値は 8 です。最も優先度の高い実行可能スレッドを選び、同優先度では実行可能順序と量子で交代します。高優先度スレッドの起床や優先度変更は DISPATCH_LEVEL 未満で次のゲスト命令より前にプリエンプトし、残りの量子を保持します。入れ子のコールバックと SEH は所属スレッドの優先度を共有します。参照が残る終了済みシステムスレッドは回収まで照会できますが、終了処理中・終了済みの変更は未対応です。借用コールバックスレッドのオブジェクトは所有スレッドの終了時に回収され、スタック再利用で以前の優先度を継承しません。

カーネル mutex の所有権は論理スレッドに属し、ネストしたコールバックと SEH をまたいで保持されます。`KeWaitForSingleObject` は遅延取得に備えて待機スレッドの識別子を保存し、所有スレッドは任意の呼び出しスタックから `KeReleaseMutex` を実行できます。通常 APC の無効化は最後の再帰解放まで続き、最外層の復帰時には未解放の mutex を拒否します。

`KeWaitForMultipleObjects` は、異なる 1..64 個の初期化済みイベント、タイマー、セマフォ、mutex、参照済みシステムスレッドに対する `WaitAll`／`WaitAny` を、非アラート可能な `KernelMode` と理由 `Executive` で処理します。`WaitAll` は全取得を一括確定し、`WaitAny` は最小の準備済み配列インデックスを返してその対象だけを消費します。3 個を超える場合は書き込み可能な非ページ `KWAIT_BLOCK` 領域が必要です。保留中は配列を保存し、全オブジェクトと呼び出し側の待機ブロックを成功またはタイムアウトまで保持します。ゼロタイムアウトのポーリングは DISPATCH_LEVEL まで、ブロック待機は APC_LEVEL までの IRQL を保存します。重複対象、アラート可能／ユーザーモード待機、mutex の放棄は未対応です。

実行可能な継続、新しいワーカー、システムスレッドは共通の準備順序を使います。入れ子呼び出しと SEH はスレッドのクォンタムを共有します。CPU 全状態、論理スレッド識別、APC、実効 IRQL、プロセスマッピングを保存します。PASSIVE/APC では切替可能、DISPATCH 以上ではスレッド切替を抑止します。クリティカル／ガード領域の APC 無効化はスレッドのプリエンプションを禁止しません。

実行中も期限順にタイマーと DMA を進めます。キャンセルはロックの解放を待ち、WDM では dispatch の復帰も待ちます。ページ可能な provider 完了、電源ポリシー、PoFx サービスは PASSIVE 境界を待ち、元の期限と実際のサービス時刻を区別します。時計が生成する独立コールバックと、ブロッキング呼び出し元の同一スレッド PoFx コールバックは所有権を分けます。待機結果は期限時点で確定し、後続のタイマー再設定やイベント通知で変わりません。1 回の命令試行が両方の期限をまたぐ場合も同じです。

Windows の優先度クラス／動的ブースト、OS モデルの並列 CPU、任意の割り込み入れ子、APC 配信、Windows ring3 のスレッド生成・スケジューリングは未実装です。CPU 並列実行は別の能力です。独自のコンパイル済みドライバーで短いクォンタム、浮動小数点／GS 状態、期限待機、交互のプロセス接続、キャンセル、PoFx 継続を検証します。ARM64 ネイティブ OS の検証は別途扱います。
