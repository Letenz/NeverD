# インタープリターのソース復元

実験的なインタープリター特化処理は、リンク済みの x64 関数から静的に解決できるディスパッチを除去し、実行時入力、メモリへの作用、分岐、ループを残します。ハンドラーの特徴や特定の保護ツールのオペコード表ではなく、命令の意味論に基づいて動作します。

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control` は、インタープリターのコンテキストを区別する汎用レジスタ全体を選択します。複数回指定できますが、具体値を与えるものではありません。たとえば、入口のコードが値を設定するバイトコードカーソルを指定します。カウンターに使う実行時入力は動的なまま扱う必要があります。異なるカーソル値が合流するとき、コンテキストの分離が不足していれば復元が停止することがあります。これを補うためにディスパッチ先を推測することはありません。カーソルがスタックへ退避される場合、`--vm-control-stack=-16:8` で入口 RSP から 16 バイト手前の 8 バイトを選択できます。このオフセットの基準は関数入口であり、調整後の現在のスタックポインターではありません。

C API は `neverd/sdk/NeverDCAPIDevirtualize.h` の `neverd_devirtualize_source_v1()` です。独立したトランザクションで実行し、セッションの通常の逆コンパイルキャッシュを変更しません。失敗時はソースを返しませんが、JSON 診断を返すことはできます。返された両方の文字列は `neverd_free_string()` で解放します。

## 制御状態の自動検出

CLI とすべてのバージョンのソース復元 C API は、自動検出を既定で有効にします。プロバイダーに依存しない C++ API では `SpecializationOptions::DiscoverControlState = false` が既定であり、利用側が `true` を指定します。手動の `--vm-control` と `--vm-control-stack` は引き続き任意のコンテキストキーです。通常の自動検出フィールドは、有界な有限値の同時関係だけを保持し、コンテキストキーの追加や実行時入力の標本値への固定は行いません。以下の選択的なメモリー精密化で証明済み定数が必要になる場合を除き、通常のカウンターは動的なままです。

未解決の制御・アドレス依存から、構造化されたノード入口のレジスター入力と、メモリー入力が最初に生成されたときの由来を追跡します。狭いバイト範囲も対象です。フレームスロットを候補にするのは、その由来がノード入口から未変更のメモリーを示し、関数入口のフレームに対する正確な相対範囲を特定する場合だけです。同じ値やストアから転送された値を後から読み取っても、新しい入力依存は生じません。メモリーの情報を無効化した後に生成された未知バイトも入口のスロットとは扱いません。過去の読み取り記録は、他の解析で引き続き利用できます。欠けた依存を検出すると関数入口から解析を再開します。保持する各関係には、その関係が制約するビットについて完全な有限値証明が必要であり、別名の可能性がある書き込みは引き続きメモリーの事実を無効化します。任意の外部メモリーや無界な相関値を有限化するものではありません。

生産側への要求は、ノード境界を越えてビットマスクを保持し、バイト全体へ切り上げません。ただし算術演算では、要求されたビットに桁上がりや桁借りを伝える可能性がある下位ビット列を保守的に含めます。

追跡済みのメモリー依存により正確なアドレスの証明が繰り返し妨げられる場合、追加の精密化で証明済みの流入定数をコンテキストキーに昇格できます。複数値の組を新しいエッジへ分割したり、コンテキスト選択のためにゲストメモリーの読み取りを追加したりはしません。有限値の証明だけでは追加読み取りの安全性を示せないためです。動的または無界なメモリー依存状態では、設定された上限内で復元が停止することがあります。

この選択的な精密化では、入口フレームの基点に正確な変位を加えた値と証明された、完全な 64 ビットレジスター値や退避済みポインターもコンテキストを区別できます。キーは変位を保持し、呼び出し時の数値アドレスを推測しません。部分書き込みや別名の可能性はポインターの事実を無効にします。条件分岐は、精度不足の合流によって未対応の後続処理が現れた場合を含め、最終制御証明の前に有界な精密化の依存候補を提案できます。候補は条件が偽である証明ではありません。到達可能性と保持する宛先は完全な証明を要し、未対応処理が到達可能なまま、または必要な予算が尽きた場合は公開しません。未対応の後続処理に対する候補探索は、直近の条件未確定な先行分岐を選びます。完全な後方スライスではありません。

生産側への逆向き要求は、ネイティブノードの入口、命令モード、フィールドの種類とバイト範囲で識別します。後続ノードがそのフィールドを必要とするエッジだけが生産側の依存を展開し、有限でも精度が不足する値域も対象にします。これにより予算内で入口から再解析することがありますが、再利用される物理レジスターに全体で一つの役割を割り当てることはありません。依存検出は有界で不完全であり、すべてのインタープリターを手動ヒントなしで復元できる保証はありません。

通常の自動検出フィールドの射影も、遷移先ノードの要求に限定します。定数でないフィールドをエッジの有限値の同時関係に含めるのは、遷移先がそのフィールドを要求する場合だけです。手動フィールドと、自動的にコンテキストキーへ昇格したフィールドは、引き続き全体で射影の対象になります。既知の定数バイト、関数入口のフレームに相対的な正確なポインター、および由来の情報は、要求の有無にかかわらず保持します。これにより、異なるハンドラー段階の無関係なフィールドが値の組み合わせを乗算的に増やすことを防ぎます。設定された予算と、制御の遷移先、メモリーアドレス、戻り時の状態に必要な証明条件は変わりません。

通常の自動フィールドでは、各組の列は要求されたビットだけを制約し、対応するマスクを持ちます。合流では、すべての流入経路で制約されているビットだけを保持します。同じバイト内の他のビットは実行時の値のままです。フィールドの格納範囲は、その範囲全体について完全な有限値域が証明されたことを意味しません。バイトを定数にできるのは、8 ビットすべてが定数であると証明された場合だけです。

手動フィールドとコンテキストキーへ昇格したフィールドは、引き続き全体で全幅の関係の証明を先に試みます。その証明で結論が得られない場合は、要求されたビットの関係だけを保持できます。未証明のバイトをコンテキストキーへ渡したり、使い切った全体予算を回避したりはしません。

新しいグラフで解析を再開するとき、他のフィールドに完全に含まれる通常の自動格納範囲は、その広いフィールドを共有できます。元の段階の位置とビット要求は変わりません。手動フィールド、コンテキストフィールド、未解決のメモリーアドレスから直接候補になったフィールドは、正確な範囲を保持します。`MaxControlFields` は、この正規化後に実際に保持するフィールド数を制限します。`DiscoveredControlFields` は累積値のままで、有効なフィールド数を超えることがあります。フィールド数の上限と全体の処理予算は引き上げません。

完全な有限値域の証明が得られた通常の自動フィールドについては、すべての生産側入力を直ちに制御フィールドへ追加しません。検出処理はこれらの依存候補を記録し、復元がなお阻まれ、直近の精密化で候補が得られない場合にのみ有効化します。コンテキストキーへ昇格したフィールドは、引き続き生産側の依存を直ちに展開します。検出の訪問数、再解析、証明処理には従来の累積予算を適用します。

試行が失敗して通常の候補選択を終えた後、有界の逆向きワークリストが、観測済みのネイティブ制御遷移を通じて未処理の正確なビット要求を伝播します。共通のスカラー評価器を再利用し、現在の制御フィールドが保持する範囲だけを扱うため、フィールドやコンテキストは追加しません。古いグラフは候補の伝播経路にのみ使用し、その値や経路の実行可能性を新たな事実として取り込みません。先行ノードの走査、再実行、依存関係の検出は累積作業予算を共有します。これにより、長い連鎖でもネイティブ段階ごとの完全な再解析を避けて要求を伝播できますが、公開には新しいグラフでの完全な固定点証明が必要です。

完全な有限値域からは、ワード全体の値が変化していても、個々のバイトが定数であることを証明できます。例えば、値域 `{0, 0x100}` の最下位バイトは常にゼロです。列挙されたすべての組で等しいバイトだけを、対象のバイト順に従って定数として保持し、他のバイトは動的なまま残します。不完全な列挙、ソルバーの不明という結果、証明予算の枯渇から、このような事実を得ることはありません。

有限値域の証明は、精密化による再解析を含む 1 回の復元処理内で再利用できます。有界キャッシュは、自由変数の一貫した名前変更を許しつつ、完全な順序付き式 DAG を比較します。変数の共有関係、幅、定数のビット、演算子の付加情報、射影上限はキーに残ります。完全な値域と、値域が上限を超える証明だけを保存します。不明または部分的な結果は保存せず、未ヒットや容量不足では通常の証明経路を使います。全体予算はすべて引き続き適用し、`solverQueries` は実際のソルバー呼び出しを数えます。

同じ述語の下で到達可能性が証明されていれば、値が変化する 1 列の完全な値域と、他の各列について証明された唯一の値から、正確な同時関係を決定できます。複数の列が変化する場合は、引き続き同時の証明が必要です。マスクされた列がその全ビット値域を覆う場合でも、入力ビットが述語および他の全列から独立していると証明した場合だけ省略できます。共有入力、不明な結果、不完全な列挙から直積を仮定することはありません。

既定値は手動・自動フィールド合計で `MaxControlFields = 16`、`MaxControlRefinements = 16`、`MaxDiscoveryVisits = 65536` です。再解析は全体のノード数（合成ノードを含む）、操作数、評価数、求解回数、検出訪問数の予算を共有します。`contexts` はネイティブコンテキスト数であり、`evaluatedOperations`、`nodeEvaluations`、`solverQueries` と同様に試行間で累計します。アドレスごとのコンテキスト数、使用中のネイティブ復帰スロット数、フィールド数、組の数は各試行内の構造上限です。求解回数の既定上限は 4096 のままです。予算切れで部分結果を公開せず、`residualBlocks` は最終残余グラフだけを表します。

CLI オプション `--vm-max-refinements=N` は正の整数を要求し、既定値は 16 です。C の呼び出し側は `neverd_devirtualize_source_v2()` または `neverd_devirtualize_machine_source_v2()` で同じ上限を設定できます。`neverd_devirtualize_options_v2` をゼロ初期化し、`base.struct_size = sizeof(neverd_devirtualize_options_v2)` と `max_control_refinements` を設定します（ゼロなら既定値 16）。埋め込まれた `base` に v1 のオプションを保持し、2 つの reserved メンバーはゼロのままにします。既存の v1 レイアウトと入口は変わらず、拡張末尾を無視します。他の処理予算と証明予算も引き続き適用されます。

`--vm-max-fields=N` と `--vm-max-queries=N` は制御フィールド数とソルバー問い合わせ数の上限を設定し、既定値は 16 と 4096 のままです。これらと `--vm-max-refinements` は正の 32 ビット十進整数と `--devirtualize` を必要とし、ゼロ、符号、十六進数、末尾文字、桁あふれを拒否します。両方のソース ABI とバックエンドに同じ上限が適用されます。予算の増加は解析量を増やすだけで、制御ヒント、実行時入力、新たな証明保証を与えません。予算超過時は C を公開しません。

C では `neverd_devirtualize_source_v3()` または `neverd_devirtualize_machine_source_v3()` を使用します。`neverd_devirtualize_options_v3` をゼロ初期化し、`base.base.struct_size = sizeof(neverd_devirtualize_options_v3)` を設定します。`max_control_fields`、`max_solver_queries`、必要なら `base.max_control_refinements` を指定し、ゼロは従来の既定値を選択します。3 個の reserved フィールドはすべてゼロにします。v1/v2 は reserved を含む v3 末尾を無視し、v3 は将来の拡張末尾を無視します。レポートは実際の処理量と有効な `maxControlFields`、`maxControlRefinements`、`maxSolverQueries` を記録します。

JSON レポートには `discoverControlState`、`maxControlRefinements`、`maxDiscoveryVisits`、`discoveredControlFields`、`discoveredContextFields`、`controlRefinements`、`discoveryVisits` が追加され、有効な動作、上限、解析作業量を記録します。フィールドの検出だけでは復元成功を証明しません。

## 実行契約

現在のバイナリアダプターは、マッピングされたアドレスにあるリンク済み x64 ELF / PE イメージを受け付けます。マッピング、バイト列、アクセス権は固定され、並行して変更されないことが必要です。到達可能な機械語を厳密にオンデマンドでリフトします。未対応の命令、呼び出し、不透明な操作、メモリ順序を伴うアクセス、未解決の制御フロー、言語レベルの例外処理に遭遇すると復元を停止します。

PE の復元には、イメージ全体の再配置情報と例外レコードを含む完全なメタデータが必要です。CLI はこれらを読み込んでから `--func` を適用します。C API の呼び出し側は、先に `neverd_session_restrict_function()` でセッションを制限してはいけません。省略したメタデータから修正箇所や例外エッジの不在は証明できないため、バイナリアダプターは関数集合を限定してロードしたイメージを拒否します。

イメージの読み取りを定数とするには、その範囲全体がファイルに裏付けられた読み取り専用領域であり、マッピングの重複やローダーによる修正がないことを確認できなければなりません。書き込み可能な表、未解決の再配置、実行時に採取したスナップショットは、不変の読み取りを示す証拠にはなりません。COPY 再配置と構造が不完全な例外ディレクトリは拒否します。PE のディレクトリと関数範囲が完全なら、別の関数にある未解読のハンドラーは現在の入口の解析を妨げません。ただし、そのハンドラーが覆うコードに到達すると回復を拒否します。

ソース復元の対象には通常の ABI による復帰が必要です。外部由来のアドレスを使うすべてのストアについて、書き込み先の範囲が入口の戻りアドレススロットと重ならないことを要求します。これは呼び出し元／実行環境が満たすべき明示的な前提であり、外部の整数から計算したアドレスも含みます。フレーム由来の情報がないだけでは、数値アドレスが重ならないことを証明できません。フレームから派生したストア先は、このスロットと重ならないことを証明する必要があります。また、復帰時には元のスタックポインターに戻っていなければなりません。由来の情報は退避・再読み込みや合流を越えて保持され、アフィン式が失われても外部ポインターとして扱い直すことはありません。スタックの切り替え、呼び出し先が余分にスタックを解放する復帰、RET によるディスパッチは現在拒否します。バイナリアダプターは x64 のリトルエンディアン意味論を適用します。

この処理が生成するのは解析用のソースと IR です。再配置、アンワインド、非同期例外、バイナリ置換の安全性を保証するものではありません。patch モードではこのオプションを拒否します。すべてのインタープリターや保護設定への対応を意味するものでもありません。

形状が厳密に一致する x64 の `PUSHFQ`／`POPFQ` は残余プログラムに保持します。解析では機械フラグの各スナップショットを未知の実行時値とし、リフターが別途モデル化した算術フラグを合成します。フラグの復元も実行時の作用として残ります。未知のフラグに由来するアドレスに外部ポインターの戻りアドレス領域非重複契約は適用できず、派生するディスパッチ先が有界と証明できなければ復元は失敗します。

フラグ全体を保存する前に、モデル化された算術フラグと方向フラグのすべてが復元対象の関数内で定義されている必要があります。フラグを直接読み取る場合も、記号的な簡約で値が相殺されても、到達可能なすべての先行経路で定義されていなければなりません。そうでなければ、未知レジスターのトラップを含む C ソースを出力せずに復元を拒否します。

LowIR の一時値は、リフトした各ネイティブ命令内だけで有効です。読み取る各バイトは同じ命令内で先に定義されている必要があり、前の命令で使ったオフセットや、未定義値が代数的に相殺されることはソースの正しさの証拠になりません。入口定数で束縛できるのは物理レジスターだけです。

## 明示的なマシン状態の復元

```sh
neverd decompile program --func entry --devirtualize --vm-machine-state \
  --recovery-report machine-report.json -o machine.c
```

`--devirtualize --vm-machine-state` または `neverd_devirtualize_machine_source_v1()` は専用のソース ABI を選択します。引数は整列した 17 個の `uint64_t`（RAX、RCX、RDX、RBX、RSP、RBP、RSI、RDI、R8〜R15、RFLAGS）へのポインターです。64 ビット符号なし戻り値がゼロの場合のみ成功です。非ゼロではメモリ書き込みを取り消しません。状態は最後の RET が戻り先を取り出す直前です。状態領域はゲストメモリと重複できず、元のマッピングと 64 ビットリトルエンディアンホストが必要です。

元のゲストコードとデータのアドレスは、出力レジスターで観測されるものも含め、正確な数値を保持します。ソース生成によって生成プログラムのグローバルオブジェクトのアドレスへ置き換えてはなりません。必要な元のゲストマッピングは呼び出し側が用意し、C の生成はゲストアドレス空間の再配置を行いません。証明と復元レポートは引き続き元の入力イメージを参照します。

条件は CPL3/IOPL0、シャドウスタック無効、非同期イベントなし、通常の非フォールト実行です。入口フラグは正規値で TF/RF/VM/AC/VIF/VIP がゼロ、POPFQ では TF/AC がゼロであることを生成ソースが確認します。PUSHFQ/POPFQ は明示状態を使用し、RDSSP は宛先を保持します。到達した INCSSP は拒否します。完全なフレームポインター保存は伝播でき、部分書き込みや別名の可能性で無効になります。例外メタデータを持つコードも通常経路のみ対象で、例外配送・アンワインド等価性は保証しません。報告の `sourceABI` と `executionProfile` に条件を記録し、既定 ABI の厳格な規則は維持します。

この機械状態 ABI は直接 near CALL と、有限の宛先集合を網羅的に証明できるレジスター間接 near CALL を扱います。レジスター間接呼び出しは RSP の変更前に元の宛先レジスターを取り込み、実際の次命令アドレスを一度だけ書き込みます。内部 near RET は完全に証明された有限宛先集合から選択できます。残余コードはゲストスタックを一度読み、その値を保持してからスタックポインターを増加させ、保持値で分岐します。保存された入口の戻りスロットに到達すれば、内部フレームを破棄した後でも外側への終了です。未知の宛先、欠落または実行不能な宛先を含む集合、引数を追加でポップする戻り、任意のスタック切り替えは拒否します。

メモリー間接 near CALL も、この明示的機械状態 ABI、シャドウスタック無効、通常の非フォールト実行という条件でのみ対応します。メモリーオペランドはセグメントオーバーライドのない正規の `r/m64` 符号化に限定し、アドレスサイズオーバーライド（`addr32`）と REX は任意です。共通の x64 実効アドレスと LOAD の意味論で宛先を読み、その後に RSP を変更して実際の次命令アドレスをプッシュします。プッシュが宛先スロットを上書きする場合も同じ順序であり、スロットのアドレスを読み込んだ呼び出し先と取り違えません。読み取り専用のポインタースロットや有限テーブルには不変読み取りの証拠が必要で、初期化が証明されたゲストスタック値にも完全な有限宛先の証明が必要です。書き込み可能スロットの初期イメージや実行時スナップショットは不変性の証拠ではありません。未証明の外部読み取り、失効したスタックの事実、不正な宛先、FS/GS などのセグメント指定、far CALL、余分または非正規のプレフィックスは拒否します。既定のソース ABI は引き続きネイティブ呼び出しを拒否します。

既定の通常ソース ABI は呼び出し専用のフレームを再構築します。外部由来のすべての LOAD/STORE 範囲（計算したアドレスを含む）は元の専用フレームおよび再構築後のソース側ストレージと重複しないことが明示的な前提です。共有証明はフレームアドレスの流出、アドレスに依存する結果や分岐、未初期化バイトの読み取りを拒否します。明示的マシン状態 ABI は元のゲストアドレスを保持し、この専用フレームの前提を使用しません。

未定義フラグが制御フロー、アドレス、または定義済みの出力に影響する場合、それらへの非干渉を別途証明する必要があります。現在の復元レポートはこの証明を提供せず、プロセッサ依存の動作を保証しません。

## 共通実装

`SpecializationProvider` が完全にリフトされた命令と、不変の読み取りに関する証拠を提供します。`NeverDInterpreterSpecialization` は既存の `SymExec` の意味論を用いて、整数操作と制御操作を部分評価します。バイナリアダプターはマッピングと命令デコードを担当し、別の命令評価器を実装しません。

有限のシンボリック読み取りアドレスに対して、組み込みのビットベクトルソルバーが現在の制約の下で候補を列挙します。最後の UNSAT により他のアドレスが存在しないことを証明し、全候補に不変かつメモリ障害を起こさない読み取りの完全な証拠がある場合だけ、その集合を採用します。このように証明された LOAD は、LowIR でアドレスを一度保存して正確な値を選ぶ SELECT の連鎖に置き換えられます。証明されていない通常の読み取りは動的なままです。一つの採取アドレスで集合全体を代用しません。選択した制御レジスタと入口フレームスロットの有界な組の集合をノード間で保持し、カーソルとデコードキーなどの関係を維持できます。合流と拡大は保守的に行います。部分的な SAT の標本やソルバーの unknown は、アドレスやターゲット集合の完全性の証明ではありません。この機構は任意機能の Z3 バックエンドを必要としません。

ノードはネイティブ命令カーソル、命令モード、選択した制御レジスタおよび入口フレームスロットの定数で識別されます。その他のバイト単位の事実は共通部分を取って合流します。流入する事実が弱まった場合は、そのノードを再評価します。これにより、プログラム本来のループを、観測された反復ごとに展開せず、ループとして残せます。間接ターゲットのすべての到達可能な値は、網羅性が証明された有界な集合に属していなければなりません。解決されたターゲットは、残余コード内の明示的な比較と CFG の辺に変換されます。

動的な操作と通常の load/store は LowIR に残ります。スカラー定数、入口フレームに対するアフィンなポインター、定数であると証明されたフレームのバイトはノード間を伝播できます。その他の式は無制限に展開せず、破棄します。フレームメモリには、既存のシンボリック状態の保守的なエイリアス無効化を適用します。エイリアスの可能性がある未知のポインターへの書き込みは、矛盾する事実を無効にします。スタックスロットを私有領域と仮定したり、未証明の非エイリアス契約によって消去したりはしません。

複製したコンテキストは一意の合成命令ラベルで区別します。元の命令境界は別の由来マップに保持し、元の再配置、例外、ジャンプテーブルの証明情報を新しい命令実体へコピーしません。復元した LowIR は HighC/LLVM の分岐より前で通常の LowIR-to-MedIR 変換に入り、レジスタ、スタック、CFG、SSA、ABI の処理を共有します。HighC 経路でも、復元には MedIR 検証の成功が必要です。

ノード数、アドレスごとのコンテキスト数、操作数、ノードの評価回数、有限ターゲット数の予算で解析量を制限します。予算超過や未対応の意味論がある場合、残余関数は公開しません。制御グラフが完全であることとソース生成の成功は別の条件です。公開 API は両方を検査し、区別して報告します。

有限読み取りアドレス集合、制御値の組、制御フィールド数にも明示的な上限があります。ソルバーへの問い合わせ総数と、各問い合わせのゲート、衝突、伝播、監視リテラル参照の上限で証明処理を制限します。シンボリックノード数にも上限を設けます。JSON レポートにはこれらの予算と `solverQueries`、`relationalWidenings` を含めます。

## 証拠とテスト

任意のローカル JSON レポートには、入力のダイジェスト、選択した制御項目、予算、状態、処理量のカウンター、残余ブロック数、元の命令位置、復元で使用した不変のバイトが含まれます。入力由来の情報を含むため、指定されたローカルパスにだけ書き込みます。

公開テストは、独自に作成したレジスタ型のスレッデッドディスパッチとスタック型ディスパッチのマシンを使い、それぞれ算術、分岐／合流、実行時ループのプログラムを持ちます。独立した符号なし演算の参照実装で、戻り値、メモリへの書き込み、桁上がり／借り、出力のカナリアを確認します。復元した HighC と LLVMC は、未定義動作トラップを有効にして O0/O2 でコンパイルし、参照実装と実行結果を照合します。負のケースでは未解決のディスパッチ、書き込み可能なディスパッチ表、非互換のバイト順、例外メタデータ、予算を検証します。

追加の独自の有限アドレス fixture は、入力で選ぶ読み取り専用レコード、相関のあるカーソル／キー制御フィールド、異なる仮想位置で再利用する同じハンドラーを使います。分岐／合流と、実行中のプログラム状態によってレコードを選ぶループを対象にします。独立したネイティブ参照実装は SysV と Win64 の両呼び出し規約を使います。両方の復元 C 経路を O0/O2、未定義動作トラップ、出力カナリアで確認します。読み取りの証拠不足や証明予算不足で部分的な結果を公開してはいけません。

拡張テスト行列では、直接スレッド化ポインターバイトコード、有界なソフトウェア CALL/RET スタックと入れ子の仮想呼び出し、回転するオペコード復号状態を持つループという三つの独立形態を、手動制御ヒントなしで復元することを要求します。ネイティブ SysV/Win64 と復元後の HighC・LLVMC を O0/O2 で独立した数学的参照実装と照合し、出力カナリアも確認します。未知の仮想戻りカーソル、制約のない復号キー、予算切れではソースを公開しません。

別の機械状態行列では、ネイティブ実行と両方の復元 C 経路について、O0/O2 で全 16 汎用レジスター、定義済みフラグ、テスト対象ゲストスタックの全バイトの一致を要求します。レジスター間接 CALL の呼び出し先は宛先レジスターを読み取り、上書きします。戻りスレッド化分岐は既知の宛先を選択します。参照実装は次命令アドレスの実際の保存、フラグ保持、RSP 復元を検証し、期待するコードアドレスはシンボルから取得します。未知・不正な宛先集合や証明されていないメモリー上の宛先はソースなしで失敗する必要があります。これは独自 fixture の検証要件であり、任意の仮想マシンや保護製品への対応保証ではありません。これらの独自 fixture は、ローカルの x64 Linux で上記の検証を通過しています。

公開メモリー呼び出し fixture は、不変の RIP 相対ポインタースロット、入力で選ぶ有限の読み取り専用テーブル、初期化済みで宛先が有限のゲストスタックスロット、CALL 自身のプッシュで上書きされる宛先スロットを対象にします。ローカルの x64 Linux では、この四つの形態それぞれについて 1,024 状態を、ネイティブ実行、HighC、LLVMC の O0/O2 で検証しています。独立参照実装は全 17 状態ワードと 128 バイトのゲストスタックを比較し、呼び出し先が観測する戻りアドレスも含めます。未証明の外部・書き込み可能スロット、別名書き込みで壊れたスタック値、不正な宛先、既定ソース ABI 経由の呼び出しは公開を拒否します。

別の固定アドレス実行回帰では、元の入力イメージのアドレスに書き込み可能なゲストメモリーを用意します。両 C バックエンドは O0/O2 でそのマッピングを読み書きし、出力レジスターで元のゲストアドレスの数値を保持し、隣接カナリアを変更しないことが必要です。生成されたグローバルオブジェクトへの置き換えは、この参照実装を満たしません。これらのローカル検証は任意の VM への対応を意味しません。

専用のテストターゲットは [testing.md](testing.md) を参照してください。

## ループ証明候補の自動推論

以下の前置経路述語を保持する要件は `GeneralizeEntryPrefix = false` の場合に適用します。

`inferLowIRLoopRefinementPlan` は共有シンボリック実行器で予算内のテンプレートを提案します。フィードバック切断点は CFG の全閉路を覆い、拡大は証明済み固定ビットを維持し、保存されない符号なし接頭辞境界を除きます。観測した単位増減カウンタと推論した段階定数から辞書式順位を構成し、増加・減少する入れ子ループを扱います。`OriginalPrefix` と `CandidatePrefix` には `UseEntryPrefix` が必要です。先行切断点の後にある切断点は、実際の入口から別途有限再実行して到達可能な対応接頭辞を取得できます。この証拠は入口領域全体を覆いません。各到達状態がその述語を含意し、入口と遷移の完全な経路網羅が必要です。`inferAndCheckBinaryLowIRLoopRefinement` は完全な復元と一意のネイティブ由来を要求し、元プログラムと候補の完全な検査を独立に再実行します。提案と由来対応は信頼せず、証明書を持てるのは `Refinement` のみです。推論と証明は別々の明示予算を使います。この C++ API は `--devirtualize` で自動実行されません。到達不能な接頭辞、任意の制御対応、探索外の順位形式、C バックエンド等価性、実 CPU の未定義ビット選択は未対応です。

`GeneralizeEntryPrefix` の既定値は `false` で、`UseEntryPrefix` が必要です。既定モードでは、すべての到達で取得した経路述語を保持します。明示的な汎化モードは、経路外の前置状態式を全域の未検証テンプレート関数として扱います。実行可能な両側の証人、実入口と区間の完全な網羅、全レジスタ／フレームの一致、引数の射影、ネイティブ実行条件、拡大した帰納領域での厳密な順位減少が必要です。推論は流入状態が証人の領域を越える場合だけ切点を拡大し、すべての一般遷移を再構築して検査します。最初の証人がゼロ回反復でも、別の入口のループを見落とせません。方針は帰納証明書のダイジェストに結び付きます。

多重ループの推論は、観測した単位増減カウンタと制御述語が参照する不変の前置値との間で、厳密／非厳密な符号なし境界を提案できます。等値による終了も対象です。具体的な入口と流入状態で検査した後、一般流入遷移で成立しない関係を単調に除去します。述語走査とソルバ処理は既存の明示的な推論予算を使い、最終の原プログラム／候補チェッカーがテンプレートを独立に証明します。

入れ子ループの推論は、前置状態の式が一致する場合、キャッシュされたオペランドとカウンターまたは不変の制御入力の等式も提案します。すべての具体的な流入状態を検査し、後の拡大で発見されたキャッシュにも候補を用意し、一般化された流入状態が関係に違反すれば削除します。各ワードは復元可能な独自のパラメーターを保持し、等式は検査対象の述語です。コピーの漸化式は不要な固定ビットの除去を速めますが、意味を仮定しません。

入れ子ループの推論では、変化するビットが最大 16 個のフィールドについて、カウンタの等値・不等値比較を保存する関係も探索します。関係は現在のカウンタと境界値を使い、キャッシュには独立した復元可能な状態パラメータを保持します。入口ガードや定数畳み込みされた初期値により比較が後の拡幅まで現れない場合、新しい候補を追加できますが、拒否・削除された候補は再追加しません。候補は保存済みの全具体到達状態と現在の全入力遷移で成立する必要があります。変数 DAG の走査は切点ごとにキャッシュし、共通の述語予算に計上します。完全なネイティブ経路網羅、全状態の等価性、厳密なランク減少は独立に検証します。 一般遷移後もカウンタの発見を続けます。最初の内側ループの証拠では見えなかった外側カウンタにも、検証済みの境界とオペランドコピーの候補を与えます。拒否した関係は復活させず、単位増減の探索にもシンボリックノード予算を適用します。

入口プレフィックスの再実行は、先のループをさらに展開する前に待機中の分岐を訪問します。別の分岐が任意回数の反復を許していても、短い到達可能な証拠を探索できます。推論と元プログラム／候補プログラムの検査は同じ順序規則を使います。すべての処理は従来の予算に計上され、プレフィックスの証拠は完全な入口網羅、不変条件の保持、停止性の検査を代替しません。

`pairLowIRLoopRefinementPlans` は、明示的な `LowIRLoopCutpointPair` により独立に提案された二つの自己関係計画を結合します。各カット点は一度だけ対応付けます。`SharedInputs` は同じ幅の帰納入力間に等価述語を追加し、検査器が検証できるよう両側の束縛と射影を保持します。他の一時値は独立のままで、候補側の前置入力には `CandidatePrefix` を使い、両方の述語と原側のランクを保持します。`UseEntryPrefix` は両計画で一致する必要があり、どちらかが必要とすれば `GeneralizeEntryPrefix` を有効にします。一時値の定義は重複不可で、使用幅は厳密に一致させます。`MaxMetadata` の既定値は 65536 で、コピー前に構築量を制限します。結果は未検証の提案です。`checkLowIRLoopRefinement` による完全な網羅性、状態とフレームの一致、観測結果、厳密な進捗の独立検査が必要です。この補助 API は証明書を発行せず、CLI の既定値も変更しません。
