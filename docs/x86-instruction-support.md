## Support is a pipeline property

Decoder recognition, strict LowIR lifting, executable LLVM/C output and
software emulation are separate capabilities. A switch label does not prove
any of them. Valid instruction forms can also differ in operand width,
encoding, mask, rounding, segment or addressing mode.

The pinned decoder has 1,652 instruction IDs. Twenty IDs without literal
mentions in the lifter are generated by the floating-point family macros in
`X86FPArithState.h` and `X86FPPackedConvertState.h`; they are not missing
implementations. The previous source-text coverage script cannot establish
complete instruction support or semantic test coverage.

## Completed in this change

| Instructions | Implementation and verification |
| --- | --- |
| RDPID | Explicit natural-width query result; ordered hardware effect. |
| RDFSBASE, RDGSBASE, WRFSBASE, WRGSBASE | 32/64-bit operands in long mode; explicit read/write direction. |
| CLTS | Ordered processor-state effect with no fabricated register output. |
| UMONITOR | Address-size wrapping and FS/GS offset ownership; no ordinary preload. |
| UMWAIT, TPAUSE | Explicit control operand and EDX:EAX deadline; actual CF completion; other arithmetic flags cleared. |
| LAR | Actual ZF completion; failure preserves the entire destination, including the upper half of a 32-bit destination in long mode. Memory selectors remain instruction-owned. |
| ARPL | 32-bit target only; actual ZF and adjusted selector; conditional memory write remains inside the instruction. |
| VSHA512MSG1, VSHA512MSG2, VSHA512RNDS2 | Integer LowIR, independent scalar oracle, source aliasing, upper-lane clearing and executable LLVM/HighC/LLVMC tests without SHA512 hardware. |
| VMASKMOVPS/PD and VPMASKMOVD/Q stores | A void output replaces an invalid zero-width RAX result. Tests cover both vector widths, both architectures and inactive lanes over unmapped memory. |
| Shared 32-bit VEX3/EVEX register and address validators | Mode-aware register-bank selection for their callers, including F16C, FMA4, SHA512 and EVEX integer/vector families. Ignored extension fields select the low bank; reserved fields still fail clearly. |
| REX2 and 32-bit VEX floating-point forms | Shared prefix validation replaces eight local parsers. The 13 previously failing REX2 and nine 32-bit VEX examples now strictly lift, retaining distinct GPR/vector/address extension rules. Concrete and executable source/native-route regressions cover the new behavior. |
| WRSSD/Q, WRUSSD/Q, ENQCMD and ENQCMDS native output | The shared system contract emits the real instruction in LLVM, HighC and LLVM-to-C. Memory stays inside the instruction, enqueue returns its actual ZF, and FS/GS qualifies only the explicit memory operand. |

`X86SystemState.def` and `X86SystemState.h` own the system-instruction inventory
and operand/completion shapes. LowIR, Low-to-Med conversion, Med verification,
LLVM and both C routes consume that contract. `X86SystemStateAsm.h` owns the
assembly constraints shared by the emitters. No new intrinsic renumbers an
existing intrinsic.

The eleven system instructions emit real native instructions with their
memory and flag constraints. They require the architectural CPU features,
privilege and machine state at execution time. The scalar emulator explicitly
refuses these environment-dependent effects before mutating state. This change
does not introduce a virtual CPU or synthesize successful hardware responses.

The system-memory follow-up also brings the existing CET writes and enqueue
intrinsics under this contract without changing their serialized IDs.
WRSSD/WRUSSD retain their 32-bit-target forms; the qword forms require x64.
ENQCMD/ENQCMDS remain long-mode-only in the lifter: their second address is an
implicit ES destination, independent of a source FS/GS override. Their native
implementations own all permission checks and memory accesses; no compiler
preload or ordinary store is substituted. The existing scalar enqueue executor
continues to require explicit CPL/PASID state and returns retry for ordinary
memory. It does not acquire a real device portal from this change.
Windows HighC keeps MSVC intrinsics for unsegmented CET writes, including the
required header, after the common operand validation. Other source spellings
use the owned assembly contract.

LLVM-to-C now lowers masked memory operations to guarded lane accesses in its
private module clone before scalarization. Inactive lanes neither access memory
nor consume poison values. Constant expressions left by vector packing are
simplified before printing, including with pipeline optimization disabled, so
unneeded i128 expressions do not break i386 C compilation. LLVM-to-C also
supplies signed/unsigned `_BitInt(128)` aliases on i386 compilers without native
128-bit aliases, retaining 65..128-bit value operations and packed FP/MXCSR
results. General wide-integer runtime and ABI support remains unqualified.

The VEX/EVEX failures were latent mode-selection defects. The canonical prefix
structures now own register and address extension selection; all 133 callers
of the former mode-independent EVEX register helpers use that authority.
Tests retain the 32-bit BOUND/LES disambiguation and reserved-field checks.

`X86FPEncoding` now owns the floating-point prefix decision too. REX2 R4/B4
extend GPRs but are ignored for XMM operands; address registers use all applicable
extension bits. Used VEX vvvv selects the low eight registers in 32-bit mode,
while an unused vvvv field must still be all ones. Arithmetic, COMI, mask
comparison, scalar/packed conversion, approximation and ROUND retain their
family-specific rules. REX2 cannot encode ROUND's map 3.

## Known remaining gaps

| Instructions or family | Missing contract |
| --- | --- |
| VMRUN | Complete guest/host transition, including guest-modified unsaved GPRs and floating/vector state, plus the VM-exit continuation. |
| SKINIT | Machine reinitialization and nonlocal control transfer. |
| GETSEC | Leaf-specific register/state results and control transfer, including measured-environment entry/exit. |
| ENCLU | Leaf-specific GPR/flag results, enclave entry/exit/resume and asynchronous exit state. |
| ENCLS, ENCLV | Leaf-specific implicit register/flag completion, enclave memory and exception contracts. These supervisor/VMM operations should not be conflated with ENCLU's context transitions. |
| AMX native LLVM output | Versioned TILECFG/tile-state ownership, restartable strided memory, partial progress and fault continuation. Existing strict LowIR support is not native code-generation support. |
| Explicit-operand RDMSR/WRMSRNS, URDMSR and UWRMSR native LLVM output | The `X86MsrAccess` backend guard remains explicit. Operand-free legacy RDMSR uses a separate existing intrinsic. The documented VEX immediate RDMSR/WRMSRNS encodings also need decoder/lifter admission. |
| ENQCMD, ENQCMDS, MOVDIR64B in 32-bit mode | Implicit ES destination base/limit ownership. Existing 64-bit support does not prove these forms. |

MOVDIRI and MOVDIR64B also need a native direct-store review: their current
lowering uses ordinary memory operations or a full-mask store. Concrete
emulator tests for an indivisible destination update do not establish native
direct-store atomicity and ordering.

The six system mnemonics above still fail strict lifting explicitly. The
existing AMX LLVM guard remains explicit. Adding an opaque helper declaration,
bare assembly without outputs or a NOP would not close these gaps.

Completion therefore still requires extending the shared machine-state/runtime
contract for transitions and AMX, implementing the bounded SGX leaves, and
testing the remaining instruction forms. The bounded system contract added
here is deliberately not a replacement for a complete machine-state boundary.
This audit does **not** certify every encoding of the other decoder IDs.

## Work needed for complete coverage

1. Extend the shared instruction encoding audit beyond the current MC corpus,
   with separate expectations for decoding, strict lifting and each emitter.
   Include positive and negative forms for widths, register banks, masks,
   address sizes, segments and privilege-sensitive operations.
2. Define supervisor/VMM SGX completion from the documented leaf tables:
   consumed and modified GPRs, defined/preserved/undefined flags, and owned
   memory accesses. ENCLS/ENCLV can then use a bounded native contract without
   pretending that ENCLU entry/exit is an ordinary returning call.
3. Introduce a versioned complete-machine-state boundary and explicit
   continuations for VMRUN, SKINIT and the transferring GETSEC/ENCLU leaves.
   It must carry the affected integer, flag, segment, x87/SIMD and control
   state, distinguish native return, VM exit and nonlocal transfer, and reject
   states the selected runtime cannot transport. A compiler calling convention
   alone does not preserve the unsaved guest registers exposed by VMRUN.
4. Give AMX and 32-bit implicit ES destinations explicit state and access
   ownership, including partial progress, segment checks and fault order.
   Native and concrete executors must consume the same contract.
5. Validate transition and privilege behavior in an authenticated execution
   environment. Compile-only checks establish operand transport and generated
   code validity; they do not establish VM-exit, enclave or fault semantics.

## Reproducible checks

Build these targets in a configured test build (see [testing.md](testing.md)):

```sh
cmake --build build-x86 --target \
  NeverDX86InstructionCoverageTests NeverDX86SystemStateTests \
  NeverDX86SHA512Tests NeverDX86VectorEncodingModeTests NeverDX86FPEncodingTests \
  NeverDX86VirtualizationTests NeverDX86VirtualizationSourceTests \
  NeverDX86SystemSideeffectTests NeverDX86F16CStateTests \
  NeverDX86EncodingAccuracyTests NeverDLLVMCVectorTests
ctest --test-dir build-x86 --output-on-failure \
  -L '^(NeverDX86(InstructionCoverage|SystemState|SHA512|VectorEncodingMode|FPEncoding|Virtualization|VirtualizationSource|SystemSideeffect|F16CState|EncodingAccuracy)Tests|NeverDLLVMCVectorTests)$'
```

The real-encoding corpus test reads the pinned Capstone `suite/MC/X86` fixtures:
2,745 encodings spanning 468 instruction IDs. Before this change eight valid
VMASKMOVPS/PD store samples failed; after it all 2,745 strictly lift. The test
records sample and ID counts in its GTest XML properties. Its denominator is
the fixture corpus, not all 1,652 IDs or all x86 forms.

The original diagnostic scan of the decoder's C unit-test byte arrays found 298
fully consumed x86/x64 candidates. Five VEX/EVEX form failures were fixed in the
first batch; ten candidates then failed in the REX2 and 32-bit ES families.
The follow-up FP regressions address REX2 forms while the implicit ES contract
remains open. These arrays also contain negative decoder fixtures: this diagnostic
count is not an architectural validity or instruction-coverage denominator.

Source tests exercise the system instructions on ELF, COFF and Mach-O with and
without pipeline optimization. LLVM IR and both generated C routes compile
for freestanding Linux i386/x86-64 targets at `-O0` and `-O2`. COFF and
Mach-O checks cover source generation and anchors, not platform SDK compilation.
Native object checks use the repository-matched LLVM fork as well as compiling
the emitted LLVM IR with the configured Clang. Privileged instructions are not
executed on the host. SHA512 arithmetic, unprivileged failing LAR and a 32-bit
EVEX integer fixture have executable regressions in all three routes. The last
uses a freestanding i386 executable and requires Linux x86-64 with i386 execution
support; it does not require host AVX-512 instructions.

The original batch's local verification profile is Release, with the
repository-pinned LLVM 23.0.0-r6 and shared library enabled; GUI, worker and
CPU/driver emulation are disabled. The expanded `NeverDLiftTests` x86/x64/x87,
Med, Low-to-Med and LLVMC selection passes 1,825 tests. Seventeen tests are
skipped: four require native
Mach-O patch execution and thirteen require unavailable Windows EH corpus
fixtures. A further 417 EVEX/APX, undefined-effect, memory/boundary and AMX guard
tests pass. The 124 focused system, SHA512, vector-mode, source-route, F16C and
LLVM-to-C checks pass 123 tests and skip the Windows-only F16C GS-base native
oracle.

On this Linux host, Apport made the existing F16C assembly-authentication death
test take 143 seconds, exceeding CTest's 120-second limit. It also passes in
0.09 seconds with dumpability disabled in the test process. No product behavior
or global crash-reporting setting was changed to obtain that result.

After merging `dev` through `cb6678521` and updating the isolated Capstone
checkout to `b9048c86`, the same Release profile rebuilds successfully. The
broad selection passes 1,827 of 1,844 tests; the same 17 platform/corpus checks
are skipped. The focused selection above, now including encoding-accuracy
tests, passes 130 of 131 tests with the same Windows-only F16C skip. Neither
run has a failure. The 417-test EVEX/APX result above belongs to the original
batch and was not rerun for this integration. The 13 REX2 and nine 32-bit VEX
floating-point diagnostic failures were also reproduced with the new decoder.

The FP follow-up adds nine encoding-contract tests. Concrete execution checks
REX2 GPR banks, ignored vector bits, SIB/address-size/segment behavior, complete
vector state, flags and MXCSR. All four legacy ROUND opcodes additionally check
the raw map escape: generated Capstone detail omits that escape, so validating
only a presumed three-byte opcode representation incorrectly rejected them.
Wrong maps still fail before emission.

`X86FPEncodingSource.*` exercises both modes and ELF/COFF/Mach-O source routes,
then executes ELF output through HighC, LLVMC, compiled IR and the repository
LLVM fork with and without pipeline optimization. The C and external IR builds
use O0/O2. The 32-bit VEX fixture also executes original machine bytes on an
AVX-capable Linux host. The REX2 fixture does not require host APX, and no native
APX hardware oracle is claimed. External i386 builds use the same SSE2 baseline
as Codegen. The i386 65/96/128-bit carrier test separately checks wrapping,
signed comparison and arithmetic shifts against APInt at O0/O2 with
undefined-behavior traps.

Final per-test outcomes for the expanded FP/LLVM-C selection are 1,110 passed
and 20 Windows-only native checks skipped across 1,130 distinct checks. These
include the 22 scalar-state/min-max sibling checks and targeted reruns after
the ROUND map correction. Of the 57 affected checks rerun, two large ROUND
matrices exceeded CTest's 120-second limit under concurrent load; both completed
successfully in isolation in 64.70 and 54.76 seconds. There are no unresolved
semantic failures, and the test timeout and assertions were not weakened.

After integrating `5a3354cad`, the final broad selection again passes 1,827 of
1,844 tests with the same 17 platform/corpus skips. A further 289 type, LLVM-C
value, encoding, corpus and source-route integration checks pass 287 and skip
two optional kernel-type corpus checks. The Windows type generator's five
Python tests pass. All these builds use the Release profile above. Native APX,
privileged transitions, AMX completion and platform-specific skipped behavior
remain outside this qualification.

On the final `9d458aa7` decoder, the broad selection again passes 1,827 tests
and retains the same 17 skips, with no failures. All 99 selected FP contract,
encoding, corpus and source-route integration checks pass. This validates the
new decoder's table lookup and instruction-byte copy changes; the full numerical
FP matrices above were not repeated for that dependency-only merge.

After the system-memory follow-up and integration through `76dffec6e`, the
expanded broad selection passes 1,885 of 1,902 checks, with the same 17
platform/corpus skips and no failures. All 62 focused system, APX, encoding
corpus and source-route tests pass; a further 97 binary-comparison and SDK
discovery integration tests pass. The source checks cover 30 system-memory
encodings, both pipeline settings and both native word sizes. Generated ELF C
and IR compile at O0/O2, and the repository LLVM backend produces objects.
The six unsegmented CET word-size forms also compile as actual Windows-target
C using Clang's MSVC intrinsic headers. A freestanding memory declaration shim
replaces the unavailable target CRT header without altering generated bodies.
Fault probes compare signal and fault code with original machine bytes in
isolated Linux x64 subprocesses. Successful shadow-stack writes and real
device enqueue acceptance remain outside this host qualification.
