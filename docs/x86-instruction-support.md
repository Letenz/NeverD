# x86 instruction support audit

This audit starts from `f17f944a7` (the merge of virtualization support in
`367df5693`) and the pinned Capstone revision
`1d29fa3c00c916e62e23c3da7bc0cc35d2cf4c44`. It covers NeverD's 32-bit x86 and
64-bit x86 targets, not a 16-bit real-mode target.

The `dev` integration also adopts the decoder update in `cb6678521`, using
Capstone `b9048c860493ce8511f4d535526495ff273c7641`. The original audit baseline
above and the integration verification below are recorded separately.
The floating-point follow-up also integrates `39d727a54`, with Capstone
`ed51c6cbeb198c2a2d72412c8571f160ec37c30a`. The integration includes
the Windows type/ABI update merged in `5a3354cad`.
Before publication, `c17776c92` also advances the decoder to
`9d458aa76ce3b294d6ffea9f16a5b5d0cd2a6eae`.

## Support is a pipeline property

Decoder recognition, strict LowIR lifting, executable LLVM/C output and
software emulation are separate capabilities. A switch label does not prove
any of them. Valid instruction forms can also differ in operand width,
encoding, mask, rounding, segment or addressing mode.

The audit baseline has 1,652 instruction IDs; the MSRLIST decoder follow-up
appended two; the bounded-system follow-up adds eight more, bringing the
current census to 1,662. Twenty IDs without literal
mentions in the lifter are generated by the floating-point family macros in
`X86FPArithState.h` and `X86FPPackedConvertState.h`; they are not missing
implementations. The previous source-text coverage script cannot establish
complete instruction support or semantic test coverage.

| REX2 and 32-bit VEX floating-point forms | Shared prefix validation replaces eight local parsers. | WRSSD/Q, WRUSSD/Q, ENQCMD and ENQCMDS native output | The shared system contract emits the real instruction in LLVM, HighC and LLVM-to-C. Memory stays inside the instruction, enqueue returns its actual ZF, and FS/GS qualifies only the explicit memory operand. |

`X86SystemState.def` and `X86SystemState.h` own the system-instruction inventory
and operand/completion shapes. LowIR, Low-to-Med conversion, Med verification,
LLVM and both C routes consume that contract. `X86SystemStateAsm.h` owns the
assembly constraints shared by the emitters. No new intrinsic renumbers an
existing intrinsic.

The bounded system instructions emit real native instructions with their
memory and flag constraints. They require the architectural CPU features,
privilege and machine state at execution time. The scalar emulator explicitly
refuses these environment-dependent effects before mutating state. This change
does not introduce a virtual CPU or synthesize successful hardware responses.

The system-memory follow-up also brings the existing CET writes and enqueue
intrinsics under this contract without changing their serialized IDs.
WRSSD/WRUSSD retain their 32-bit-target forms; the qword forms require x64.
ENQCMD/ENQCMDS retain an implicit ES destination, independent of the source
segment. The i386 forms use the segmented block contract described below.
Their native implementations own all permission checks and memory accesses; no compiler
preload or ordinary store is substituted. The existing scalar enqueue executor
continues to require explicit CPL/PASID state and returns retry for ordinary
memory. It does not acquire a real device portal from this change.
Windows HighC keeps MSVC intrinsics for unsegmented CET writes, including the
required header, after the common operand validation. Other source spellings
use the owned assembly contract.

LLVM-to-C now lowers masked memory operations to guarded lane accesses in its
private module clone before scalarization. Inactive lanes neither access memory
nor consume poison values. Constant expressions left by vector packing are
simplified before printing, including with pipeline optimization disabled, so
unneeded i128 expressions do not break i386 C compilation. LLVM-to-C also
supplies signed/unsigned `_BitInt(128)` aliases on i386 compilers without native
128-bit aliases, retaining 65..128-bit value operations and packed FP/MXCSR
results. General wide-integer runtime and ABI support remains unqualified.

The VEX/EVEX failures were latent mode-selection defects. The canonical prefix
structures now own register and address extension selection; all 133 callers
of the former mode-independent EVEX register helpers use that authority.
Tests retain the 32-bit BOUND/LES disambiguation and reserved-field checks.

`X86FPEncoding` now owns the floating-point prefix decision too. REX2 R4/B4
extend GPRs but are ignored for XMM operands; address registers use all applicable
extension bits. Used VEX vvvv selects the low eight registers in 32-bit mode,
while an unused vvvv field must still be all ones. Arithmetic, COMI, mask
comparison, scalar/packed conversion, approximation and ROUND retain their
family-specific rules. REX2 cannot encode ROUND's map 3.

## Known remaining gaps

| Instructions or family | Missing contract |
| --- | --- |
| VMRUN | Complete guest/host transition, including guest-modified unsaved GPRs and floating/vector state, plus the VM-exit continuation. |
| SKINIT | Machine reinitialization and nonlocal control transfer. |
| GETSEC | Leaf-specific register/state results and control transfer, including measured-environment entry/exit. |
| ENCLU | Leaf-specific GPR/flag results, enclave entry/exit/resume and asynchronous exit state. |
| ERETS, ERETU, UIRET | Return-frame and nonlocal control-transfer ownership. FRED returns explicitly fail decoding instead of aliasing CLAC; UIRET is not decoded. |
| RETF/RETFQ, IRET/IRETD/IRETQ | Complete frame, privilege, segment and flag restoration. The old ordinary ABI-return approximation has been removed; strict lifting now refuses these forms. |

The direct-store execution checks cover ordinary memory. Native instructions
retain WC protocol, concurrent write completion and device transactions, but
these tests do not independently measure those properties. The concrete
emulator models only the single-threaded ordinary-memory projection.

VMRUN, SKINIT, GETSEC and ENCLU still fail strict lifting explicitly. Legacy
AMX value-form intrinsics retain their LLVM guard: an arbitrary 64-byte config
and 1024-byte tile SSA value cannot be treated as the ambient CPU bank. Decoded
AMX instructions now use the separate architectural-bank contract below. An
opaque helper declaration, assembly that loses state, or a NOP does not close
a missing semantic contract.

Completion therefore still requires extending the shared machine-state/runtime
contract for transitions, completing the ENCLU leaf/state contracts, and
testing the remaining instruction forms. The bounded system contract added
here is deliberately not a replacement for a complete machine-state boundary.
This audit does **not** certify every encoding of the other decoder IDs.
The newer MSRLIST extension is enumerated in Intel's
[June 2026 ISA reference](https://cdrdv2.intel.com/v1/dl/getContent/671368);
[SDM 093 Volume 2B](https://cdrdv2.intel.com/v1/dl/getContent/671241)
defines RDMSRLIST's memory tables, RCX mask and partial-completion behavior.
Both list instructions now have public IDs and a bounded native contract
described below. Extending this census still does not establish complete
architectural coverage.

## Work needed for complete coverage

The requested completion also includes native LLVM intrinsic support and
NeverC's builtin frontend. Architectural native assembly is a validated
intermediate implementation, not completion of that requirement. Audit
`NeverSight/llvm-project` and NeverC's embedded LLVM separately: reusable
intrinsics must preserve every result, memory effect, encoding requirement and
control continuation. Add missing IR definitions and instruction selection to
the LLVM fork, synchronize NeverC's definitions/generated tables and builtins,
and replace NeverD's assembly paths where the equivalent intrinsic is ready.
After the complete instruction work is validated, publish a new immutable LLVM
release, pin the exact commit plus every platform artifact digest, and update
NeverD's LLVM submodule and consumers together. Do not publish a release for an
incomplete intermediate batch.

1. Extend the shared instruction encoding audit beyond the current MC corpus,
   with separate expectations for decoding, strict lifting and each emitter.
   Include positive and negative forms for widths, register banks, masks,
   address sizes, segments and privilege-sensitive operations.
2. Extend the bounded SGX contract to ENCLU query/memory leaves, with explicit
   enclave execution requirements. Its entry/exit/resume leaves remain part of
   the complete-state continuation work below.
3. Introduce a versioned complete-machine-state boundary and explicit
   continuations for VMRUN, SKINIT and the transferring GETSEC/ENCLU leaves.
   It must carry the affected integer, flag, segment, x87/SIMD and control
   state, distinguish native return, VM exit and nonlocal transfer, and reject
   states the selected runtime cannot transport. A compiler calling convention
   alone does not preserve the unsaved guest registers exposed by VMRUN.
4. Qualify native AMX successful execution and fault restart on suitable
   hardware using the checked-in signal-context oracle. The shared bank
   contract and concrete partial-progress tests are implemented. A concrete
   i386 segmented executor still requires a supplied descriptor environment;
   native block transactions now retain that state.
5. Validate transition and privilege behavior in an authenticated execution
   environment. Compile-only checks establish operand transport and generated
   code validity; they do not establish VM-exit, enclave or fault semantics.

The fork generates the instruction effects from TableGen. NeverC's pruned table
has a checked generator for the same VMX effects. The old NeverC VMREAD register
instruction followed by an unconditional store was shown to overwrite the
destination on VMfail; the fixed lowering uses the actual memory instruction.

Qualification includes LLVM machine verification, O0/O2 and IR-optimized output,
ELF/COFF/Mach-O generation, and the existing VMX encoding tests. Controlled
completion tests cover 268 LLVM cases across both word sizes, 134 NeverC cases,
and 134 cases compiling NeverC's actual IR through the full LLVM fork. They
check real instruction operands, full values, status results, dead-result
retention, unchanged failed-read destinations, and absence of premature memory
accesses, including unchanged and unmapped invalidation descriptors. NeverC's
25 ordinary intrinsic tests and 81 binary checks also pass.
The new builtin spellings are `__builtin_ia32_invept` and
`__builtin_ia32_invvpid`, taking a full-width selector and descriptor pointer.

Adding intrinsic IDs also uncovered two defects in NeverC's metadata sorter:
the overload bitmap did not move with the other signature tables, and only
chained DAGISel matchers were remapped. The latter had already left PCLMUL and
CRC32 patterns stale in the old compiler. The repaired generator covers both
chained and chainless patterns, keeps its baseline tables at the same revision,
and rejects ID changes that alter matcher byte lengths. Seven generator tests,
a zero-mismatch audit of all overload flags, and 12 SSE/SSSE3/SSE4/AES/PCLMUL/CRC
compilation probes qualify the metadata repair.

MSR qualification, including WRMSRNS, adds 64 LLVM cases across both word sizes,
32 NeverC cases, and 32 NeverC-to-fork cases. The i386 WRMSR tests exposed and now cover the
required custom legalization of its i64 input into EDX:EAX. The related counter
and XCR intrinsic code-generation regressions also pass.

MSRLIST adds 224 cases on each compiler route, covering full pointer/mask
transport, actual RCX results, operand liveness, memory ordering and nonvolatile
register restoration. Injected nonzero RCX completion is a compiler transport
probe, not a claim about normal architectural return or fault restart.
The fourteen port, descriptor and processor-state APIs add 264 LLVM cases,
132 NeverC cases and 132 NeverC-to-fork cases. These check access widths,
unmapped operands, unchanged sentinels, CPUID output slots and saved registers.
All four controlled-completion runners enable LLVM machine verification on
the NeverC route too. This exposed an incorrect CLI/STI dependency on arithmetic
EFLAGS; both backends now retain the processor-state effect without inventing
an arithmetic-flags input or clobber. NeverC's descriptor load/store effects
are also generated from a checked schema.

CR/DR qualification adds 1,650 LLVM cases across both word sizes, 858 NeverC
cases for each of the generic and Microsoft builtin spellings, and 858
NeverC-to-fork cases. The old NeverC lowering deleted unused register reads
and merged repeated ones at O2. The fixed lowering emits chained native reads
and expands writes to real MOVs before machine optimization; both describe
the undefined arithmetic flags. Tests cover every valid register index,
full values, dead/repeated reads, repeated writes, write/read sequences,
ordinary memory ordering, flag clobbers and nonvolatile registers. Machine
verification, O0/O2 and optimized IR, ELF/COFF/Mach-O generation, invalid mode
and selector diagnostics, 27 intrinsic tests and the 81 binary checks pass.
The new generic builtins are `__builtin_ia32_readcr`,
`__builtin_ia32_writecr`, `__builtin_ia32_readdr` and
`__builtin_ia32_writedr`. Five generator tests additionally protect the new
write pseudo's stable opcode and synchronized metadata tables.
NeverD's current CR/DR assembly bridge now declares the same arithmetic-flags
clobber, preventing compiler condition codes from surviving the access. The
source-route regression compiles 48 read/write cases across both word sizes,
all three object formats and both pipeline optimization settings; it and the
six existing virtualization source tests pass.

REP qualification adds 1,000 LLVM cases across both code modes and 544 cases
on each NeverC builtin spelling and the NeverC-to-fork route. MOVS/STOS execute
in Unicorn against a sequential byte oracle covering all widths, both DF
directions, zero/one/seven elements, unaligned overlap, zero-count unmapped
pointers, input liveness and ordinary memory ordering. Controlled completions
cover port I/O and full-width pointer/count transport. DF is changed only at
the instruction boundary and restored before C resumes; the ABI requirements
remain unchanged. This does not qualify hardware port I/O or fault restart.
The new generic builtins use the `__builtin_ia32_` prefix, including
`__builtin_ia32_movsd_rep` for the dword move. MOVS's Microsoft builtin source
type is now correctly const-qualified. All 28 intrinsic tests and 81 binary
checks pass, together with LLVM's native-string and ordinary memcpy/memset
regressions. ELF/COFF/Mach-O generation and AT&T/Intel assembly round trips
also cover a repaired `movsdi` typo in the existing REP MOVSD Intel printer.

The register-result VMREAD and memory-source VMWRITE forms add 520 full-fork
cases and 260 cases each on NeverC and the NeverC-to-fork route. Tests cover
full-width values, each result independently, discarded results, repeated
accesses with independent statuses, ordinary memory barriers, saved registers
and unmapped memory-source boundaries. The corresponding generic builtins are
`__builtin_ia32_vmread_reg(field, prior, status_pointer)` and
`__builtin_ia32_vmwrite_mem(field, source_pointer)`. The former returns the
word and performs an ordinary C store of the status byte; that pointer is not
an architectural VMREAD memory destination. Machine verification, O0/O2,
optimized IR, wrong-mode diagnostics, all three native object formats, the
29 intrinsic tests and 81 binary checks pass. The existing VMX completion
matrix remains green. Four new generator tests protect the multi-result IIT
encoding without changing older long-signature offsets; the complete overload
audit reports zero mismatches after inserting the two NeverC intrinsic IDs.

NeverC now has native `tdpbf8ps`, `tdpbhf8ps`, `tdphbf8ps`, `tdphf8ps`,
`tileloaddrs64`, `tileloaddrst164` and historical `tmmultf32ps` builtins, including
their features, immediate checks, intrinsic types, opcode tables and both
assembler dialects. Full-fork, NeverC and NeverC-to-fork qualification each pass
10,794 checks: all 336 distinct tile triples per compute operation, all load
destinations, O0/O2, ELF/COFF/Mach-O, assembly round trips, forced EVEX assembly
with high GPRs, and controlled completions with full pointers/strides, repeated
operations, tile bank inputs/outputs, ordinary memory effects and saved C
registers. These completions inject results; they do not qualify hardware AMX
arithmetic, configuration validity, cache hints, faults or restart behavior.

Both compilers reject a function that mixes physical tile interfaces with
compiler-managed `x86_amx` values. Previously, NeverC could synthesize a tile
configuration for a managed value while a physical FP8 operation used other,
unconfigured tiles; LLVM's incremental model check also missed compute/row
forms. Whole-function classification closes that gap, and invalid physical
tile indices fail in release builds too. LLVM's 38 AMX regressions, NeverC's
32 intrinsic tests, 81 existing binary checks and the complete intrinsic
overload audit pass. The table generator preserves existing opcode/feature IDs.

The twelve AMX row forms now have native NeverC builtins and matching LLVM
signatures: `tcvtrowd2ps/d2psi`, `tcvtrowps2bf16h/hi/l/li`,
`tcvtrowps2phh/hi/l/li` and `tilemovrow/i`. Results retain all 512 bits, using
float, bfloat16, float16 or integer vectors. Tile indices are constant in
`[0, 7]`; NeverC rejects nonconstant and out-of-range immediate rows, preserves
all encoded imm8 values, and retains every bit of dynamic 32-bit row operands.
Both `amx-avx512` and `avx10.2` are required through target attributes or their
`-m` switches. Dead/repeated reads remain observable, and row calls participate
in the physical/managed tile ownership check.

Full LLVM, NeverC and NeverC-to-fork routes each pass 20,570 row checks:
O0/O2, ELF/COFF/Mach-O, both assembly dialects, all tiles, every imm8, all 32
row GPR and ZMM numbers, repeated reads, four vector element types and injected
512-bit completions. A 32-result pressure case checks spill/reload flow and
Win64 nonvolatile XMM preservation. Scalar instructions execute in Unicorn;
vector moves and native AMX completions are handled by the harness, so this
does not qualify AMX arithmetic, faults, restart or hardware availability.
The new row coverage also passes 36 NeverC regression tests, the 81 existing
binary checks, all 20 generated-table checks and an overload audit with zero
mismatches. LLVM's 39 selected tests cover the existing AMX suite and the
legacy `avx10.1-256` feature spelling used by NeverC IR.

NeverC's `<immintrin.h>` also exposes standard physical `_tile_*` wrappers
for configuration, loads/stores, compute and all row forms. They call native
builtins and are installed with the x86 resource headers. Public-header
compilation passes O0/O2 for all three object formats; all 37 related tests
pass. This exposed and fixed three C23-incompatible bit casts in the existing
FP16 headers using representation-preserving copies. An isolated installed
header probe emits native AMX IR. The plugin target schema is regenerated for
the new instructions/features and earlier register-effect fixes; both target
schemas pass their generator check. Its lockstep digest changes, so plugins
must negotiate the updated schema instead of retaining old feature IDs.

LAR/LSL now have twelve native result/status interfaces, covering 16/32/64-bit
results and register/memory selectors. NeverC's spellings are
`__builtin_ia32_{lar,lsl}_{reg,mem}{16,32,64}(selector, prior, zf_pointer)`.
The memory selector is a `const void *`; the m16 access remains inside the
instruction. The ZF pointer receives an ordinary C store after completion.
These result widths name the operand size, independently of code mode. A
lifted 32-bit destination in long mode must still merge its full old register
on failure; an i32 intrinsic alone cannot retain those upper bits.

The full LLVM route passes 1,972 encoding/completion checks, and NeverC plus
NeverC-to-fork each pass 1,174. They cover independent result/ZF uses, failure
preservation, dead/repeated reads, live inputs, memory ordering, saved registers,
unmapped selector boundaries, O0/O2, ELF/COFF/Mach-O and both assembly dialects.
The two C routes additionally pass 25 real Linux x64 user-mode cases each,
comparing null and current-CS selectors with an independent assembly oracle.
LAR's undefined result bits are masked only in the comparison, not invented by
the intrinsic. The legacy `__segmentlimit` is now chained in NeverC and accepted
by the full fork. Ten LLVM regressions, optimized-IR retention, all 39 NeverC
intrinsic tests, 81 existing binary checks and 20 generator tests pass. The

## SGX supervisor and VMM completion

`X86Sgx.h` owns ENCLS/ENCLV's four natural-width GPR inputs, primary rAX
result and two auxiliary outputs (rBX and a two-byte CF/ZF snapshot).
`X86SgxLeaves.h` defines which implicit registers each leaf consumes. Unused
inputs are conditionally zeroed before the native boundary, and only EDBGRD
publishes rBX completion. EUPDATESVN therefore remains a zero-argument
operation without invented register reads or traps. Call-graph summaries and
MedIR both prune constant selections, retaining the selected value's address
provenance. All
three emitters share `X86SgxAsm.h`. The instruction keeps implicit DS accesses,
privilege checks, enclave state and memory fault ordering; no compiler preload
or ordinary memory store substitutes for an SGX access. Segment, address-size
and long-mode REX overrides are ignored. LOCK, 66H and REP forms fail strict
lifting. Runtime rAX retains its full input, while leaf selection uses EAX.

ENCLS leaves ECREATE, EADD, EEXTEND, EPA and EAUG preserve the incoming
arithmetic flags. Other documented supervisor/VMM leaves return native CF/ZF
and clear PF/AF/SF/OF; DF remains unchanged. This includes current EUPDATESVN
and the historical conflict/virtualization leaves. Native rBX completion
retains EDBGRD's data, without fabricating outputs for rCX or rDX. The assembly
saves rAX before SETC/SETZ write AL/AH, using neither stack scratch nor LAHF.
The primary result participates in the shared return contract, and unused
results cannot remove the ordered instruction. The scalar emulator refuses
SGX without an architectural environment.

The references are Intel's [SDM 093 Volume 3D](https://cdrdv2.intel.com/v1/dl/getContent/671269)
and the [earlier Volume 3D containing ENCLV](https://cdrdv2-public.intel.com/774498/332831-sdm-vol-3d.pdf).
These normal-completion contracts do not implement ENCLU transitions or an
AEX/VM-exit handler. Native execution still needs the CPU and OS SGX state.

C output uses GNU inline assembly; Windows compilation is qualified with

## i386 segmented block transactions

and privilege checks and the ordered transaction. No compiler preload or
ordinary store substitutes for it. Enqueue returns native ZF and clears the
other arithmetic flags; MOVDIR64B preserves flags.

The shared system shape and assembly plan drive LowIR validation, MedIR,
LLVM, HighC and LLVMC. Native assembly uses the original address width and
fixed SI/DI operands; source segment prefixes are independent of register
allocation. Both native arguments remain integers, so an offset matching an
image VA cannot acquire an unrelated symbol identity. The scalar emulator
refuses these operations before effects because it has no descriptor context.
This is native CPU execution support, not a new software segmentation model.

`X86SegmentedBlock.*` tests decode/detail agreement, segment selection, address
wrapping, output shapes and missing-environment refusal.
`X86SegmentedBlockSource.*` compiles all six source segments and both address
sizes for i386 ELF, COFF and Mach-O through both C routes and LLVM at O0/O2.
Linux i386 executables compare the original bytes and generated objects with
nonflat ES/FS descriptors, ES source/destination overlap, read-only ES, segment
limits and unaligned destinations. MOVDIR64B success has a separate byte and
flag oracle. Enqueue checks cover native faults, not successful CPL0 execution
or device acceptance. Windows C compilation uses Clang GNU inline assembly.
The references are Intel's [SDM Volume 2A](https://cdrdv2.intel.com/v1/dl/getContent/671199)
and [SDM Volume 2B](https://cdrdv2.intel.com/v1/dl/getContent/671241).

## Architectural AMX bank and native output

`X86AmxState.h` owns the version-1 descriptor for 28 operation kinds. The new
append-only `X86AMXState` intrinsic carries a base address, a constant descriptor,
and a stride or row selector where required. The descriptor distinguishes tile
register indices, four load hints, address-size wrapping, APX-promoted memory,
register/immediate row selection, extended row GPRs and the default SS segment.
FS/GS use the existing address-space authority. All validation layers consume
this shape; malformed versions, modes, widths and effects fail explicitly.

The operation owns the complete architectural TILECFG/TILEDATA bank. Native
LLVM and both C routes emit the real instruction with volatile ordering,
compiler memory effects and all eight TMM clobbers. Hardware retains the bank,
including partial completion and `start_row` when a tile transfer faults. There
is no tile-valued function ABI, synthetic configuration load, speculative row
preload, or implicit software runtime helper. Only the 64-byte result of a row
instruction enters ordinary SSA; an explicit ZMM result and private row storage
transport those bytes. LLVM allocates this storage once in the entry block.

`TILERELEASE` is now a native side effect instead of a series of zero copies.
`TILELOADD`, `TILELOADDT1`, `TILELOADDRS` and `TILELOADDRST1` retain their separate
instructions. APX memory uses EVEX even for low GPRs; extended row selectors
retain an extended GPR. Native memory retains the source segment, address width,
byte stride and instruction-owned feature, permission and fault checks.
Successful execution still requires the relevant CPU features and OS state
permission. Generated source uses GNU-compatible assembly, including Clang for
Windows; this does not add an MSVC C spelling for AMX.

The concrete evaluator owns the same physical bank in its register state and
reuses the existing tile/configuration arithmetic and memory evaluators. It
preserves partial tile data and `start_row` on failed memory accesses, clears
progress only on completion, and refuses missing configuration/tile state.
This is the ordinary-memory projection, not emulation of CPU enablement, XFD,
TSX or hardware cache protocols. Legacy value-form AMX intrinsics remain valid
for their existing concrete use but cannot bypass their LLVM transport guard.

The historical `TMMULTF32PS` opcode remains supported for decoded older input.
Intel withdrew AMX-TF32 in ISE revision 062, and
[LLVM removed its mnemonic in July 2026](https://lists.llvm.org/pipermail/llvm-commits/Week-of-Mon-20260706/1969009.html).
Native output therefore preserves the exact five opcode bytes and tile indices,
including the processor's actual unsupported-feature fault, rather than using
another matrix instruction. Its concrete arithmetic follows the historical
[ISE revision 059](https://cdrdv2-public.intel.com/865891/319433-059-architecture-instruction-set-extensions-programming-reference_2025-0930.pdf).
It is not counted as a currently advertised CPU extension.

The six row operations follow
[ISE revision 062](https://cdrdv2.intel.com/v1/dl/getContent/671368): both immediate
and register selectors use only bits 3:0. A row beyond the configured extent
produces 64 zero bytes and clears `start_row`; ignored selector high bits do not
raise a synthetic fault. The earlier row-chunk interpretation is removed from
the shared concrete evaluator. Out-of-range rows do not require known tile
contents, while rows that are actually read still do. Invalid configuration
and column shapes continue to fail before output publication.

Qualification uses 63 independently assembled/reference encodings, all three
native object formats and both pipeline optimization settings. HighC,
LLVM-to-C and LLVM IR compile at O0/O2, and the repository backend emits native
objects. Fixed-bank operations are checked against exact object bytes. Isolated
Linux subprocesses compare native completion or signal/code with original bytes
for every fixture. The complete configuration/load/store/release sequence and
its signal-context restart oracle compile and link on the baseline host.
The AMX hardware test checks normal row data, saved first-row bytes and
`start_row=1` at a second-row protection fault, then resumes the same instruction.
It is explicitly skipped when AMX-TILE is unavailable; this host cannot qualify
native successful tile computation or fault restart. Concrete tests cover
integer/floating arithmetic, row conversion, shape checks and partial progress.
