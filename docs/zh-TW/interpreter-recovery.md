# 直譯器原始碼還原

實驗性的直譯器特化階段會從已連結的 x64 函式中消除能夠靜態解析的派發，同時保留執行期輸入、記憶體效果、分支與迴圈。它依據指令語意運作，不依賴 handler 特徵或特定保護器的操作碼表。

```sh
neverd decompile program --func vm_entry --devirtualize --vm-control=r10 \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize --vm-control=r10 \
  --llvm -o recovered-llvm.c
```

`--vm-control` 選取用來區分直譯器上下文的完整通用暫存器。此選項可重複使用，但不會提供任何具體值。例如，可選擇由入口程式碼初始化的位元碼游標。用作計數器的執行期輸入必須保持動態。如果不同游標值在匯合時缺少必要的上下文區分，還原可能停止；引擎不得透過猜測派發目標來彌補。若游標溢出儲存至堆疊，`--vm-control-stack=-16:8` 可選取入口 RSP 減去 16 處的八個位元組。此位移是相對於函式入口，而非調整後的目前堆疊指標。

C API 是 `neverd/sdk/NeverDCAPIDevirtualize.h` 中的 `neverd_devirtualize_source_v1()`。它使用獨立交易，不修改工作階段的一般反編譯快取。失敗時不傳回原始碼，但仍可傳回 JSON 診斷。兩個傳回字串皆以 `neverd_free_string()` 釋放。

## 執行契約

二進位介接層目前接受位於其映射位址的已連結 x64 ELF 與 PE 映像。映射、位元組與權限必須保持固定，且不得並行修改。嚴格的隨需提升會沿著可達機器碼進行；遇到不支援的指令、呼叫、不透明操作、具有記憶體順序要求的存取、未解析控制流程或語言層級例外處理時，還原會停止。

PE 恢復要求完整的映像中繼資料，包括全映像重定位與例外記錄。CLI 會先載入這些中繼資料，再套用 `--func`；C API 呼叫端不得事先用 `neverd_session_restrict_function()` 限制工作階段。二進位適配器拒絕依受限函式集合載入的映像，因為省略的中繼資料不能證明不存在修正項或例外邊。

只有完整、內容由檔案提供的唯讀範圍，且沒有重疊映射或載入器修正，才能提供映像讀取常數。可寫表、未解析的重定位和執行期取樣快照，都不能作為不可變讀取的證據。COPY 重定位和結構不完整的例外目錄會被拒絕。若 PE 例外目錄及函式範圍完整，其他函式中無法解析的處理常式不會阻止目前入口分析；恢復一旦到達該處理常式涵蓋的程式碼，仍會拒絕。

原始碼還原範圍要求一般 ABI 返回：每次外部來源寫入的目標範圍，都必須與入口返回位址槽不相交。這是呼叫端／環境必須滿足的明確前提，也包括由外部整數計算出的位址；缺少堆疊框架來源資訊，並不能證明數值位址不相交。由堆疊框架衍生的寫入位址必須證明與該槽不相交，返回時也必須還原原始堆疊指標。來源資訊會跨越溢出儲存與控制流程匯合保留；遺失仿射運算式不會讓位址變成外部指標。目前拒絕堆疊切換、被呼叫端額外彈出堆疊的返回，以及以 RET 派發。二進位介接層強制採用 x64 小端序語意。

此流程產生供分析使用的原始碼與 IR，不證明重定位、堆疊展開、非同步例外或二進位替換的安全性。patch 模式拒絕此選項，也不宣稱支援所有直譯器或保護設定。

形狀精確的 x64 `PUSHFQ`／`POPFQ` 會保留在殘餘程式中。分析將每次機器旗標快照視為未知的執行階段值；提升器另行合併已建模的算術旗標。還原旗標仍是執行階段效果。由未知旗標衍生的位址不能借用外部指標與返回位址槽不重疊的契約；若其派發目標無界，復原仍會失敗。

在儲存完整旗標映像之前，每個已建模的算術旗標與方向旗標都必須已在復原的函式內定義。直接讀取旗標也要求它在所有可達的前驅路徑上已定義，即使符號化簡能抵消其值；否則復原會拒絕，而不會輸出帶有「未知暫存器」陷阱的 C 原始碼。

LowIR 暫存值只在單條已提升的原生指令內有效。讀取的每個位元組都必須先在該指令中定義；沿用上一條指令的偏移，或以代數化簡抵消未定義值，都不能作為原始碼正確性的證據。入口常數只能繫結實體暫存器。

## 目前限制

只有在設定的限制內能夠證明所需的有限取值範圍及其關聯時，才能處理依賴輸入的位元碼位址和解碼器狀態關係。這不代表支援任意間接解碼方式。證明所有派發目標後可以還原動態分支與迴圈；一般分支的測試涵蓋範圍，並不能證明支援所有此類方式。未解析控制流程與必要證明預算耗盡都表示失敗，不發布還原原始碼或部分替代程式碼。原生輔助函式呼叫、例外／重入邊界、可變程式碼與其他架構，仍不在此介接層的執行契約內。

## 共用實作

`SpecializationProvider` 提供完整提升後的指令與不可變讀取證據。`NeverDInterpreterSpecialization` 沿用現有 `SymExec` 語意，對整數及控制操作進行部分求值。二進位介接層負責映射與指令解碼，不實作第二套指令求值器。

對於有限的符號讀取位址，內建位元向量求解器會在目前約束下列舉候選位址。只有最後的 UNSAT 結果證明不存在其他位址，且每個位址皆具備完整的不可變、不會觸發記憶體錯誤的讀取憑證，才接受該集合。這類已證明的 LOAD 可以在 LowIR 中替換為位址快照與精確的 SELECT 鏈；未經證明的一般讀取仍保持動態。單次取樣位址絕不能取代完整集合。選定控制暫存器與入口堆疊框架槽之間的有界聯合元組可以跨節點保留，維持游標與解碼 key 等關係。匯合與拓寬仍採用保守規則。部分 SAT 樣本或未知求解結果，都不能證明位址或目標集合完整。此機制不依賴可選的 Z3 後端。

節點由原生指令游標、指令模式，以及所選控制暫存器和入口堆疊框架槽中的常數共同識別。其餘位元組層級事實以交集匯合。傳入事實變弱時，會重新求值該節點。因此，程式本身的迴圈仍保持為迴圈，不會逐次展開每次觀察到的反覆執行。間接目標的所有可達值必須屬於有界且已窮盡證明的集合；解析出的目標會成為殘餘程式碼中的明確比較與 CFG 邊。

動態操作及一般 load/store 保留在 LowIR 中。純量常數、相對於入口堆疊框架的仿射指標，以及已證明為常數的框架位元組可以跨節點傳遞；其他運算式會被捨棄，而非無限展開。框架記憶體沿用符號狀態既有的保守別名失效規則。透過未知且可能形成別名的指標寫入時，會使衝突事實失效。這既不假設堆疊槽為私有，也不會依據未經證明的無別名契約將其消除。

唯一的合成指令標籤用來區分複製的上下文。原始指令邊界保留在獨立的來源映射中；原始重定位、例外與跳躍表憑證不會複製到新的指令實例。還原後的 LowIR 在 HighC/LLVM 路徑分流前進入一般 LowIR-to-MedIR 轉換，共用暫存器、堆疊、CFG、SSA 與 ABI 處理。HighC 路徑的還原同樣要求 MedIR 驗證通過。

節點數、每個位址的上下文數、操作數、節點求值次數與有限目標數的預算共同限制分析。預算耗盡或語意不受支援時，不發布殘餘函式。控制流程圖完整與原始碼成功產生是不同條件；公開 API 會檢查兩者並分別回報。

有限讀取位址集合、聯合控制元組與控制欄位數量也有明確上限。全域求解查詢次數，以及各次查詢的邏輯閘、衝突、傳播與監視文字存取次數限制，約束證明工作量；符號節點上限約束運算式成長。JSON 報告包含這些預算，以及 `solverQueries` 和 `relationalWidenings` 計數。

## 證據與測試

可選的本機 JSON 報告包含輸入摘要、選取的控制項、預算、狀態、工作量計數、殘餘區塊數、原始指令位置，以及還原時使用的不可變位元組。報告包含由輸入衍生的資訊，只會寫入指定的本機路徑。

公開測試使用原創的暫存器執行緒式派發與堆疊派發機器，各自包含算術、分支／匯合及執行期迴圈程式。獨立的無號運算參考實作檢查傳回值、記憶體寫入、進位／借位結果與輸出哨兵。還原得到的 HighC 與 LLVMC 在 O0/O2 下啟用未定義行為陷阱編譯，再與該參考實作對照執行。反例涵蓋未解析派發、可寫派發表、不相容位元組序、例外中繼資料與預算限制。

新增的原創有限位址 fixture 使用由輸入選擇的唯讀記錄、相關的游標／key 控制欄位，以及在不同虛擬位置共用的同一 handler。它們涵蓋分支／匯合，以及記錄選擇隨程式執行狀態變化的迴圈。獨立原生參考實作採用 SysV 與 Win64 兩種呼叫慣例；還原後的兩條 C 路徑都在 O0/O2 下搭配未定義行為陷阱與輸出哨兵檢查。讀取憑證不完整或證明預算不足時，不得發布部分結果。

專項測試目標請見 [testing.md](testing.md)。
