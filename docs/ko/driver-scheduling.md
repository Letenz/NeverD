# Windows 드라이버 선점 스케줄링

선택적 `scheduling` 객체는 Unicorn, KVM, WHP의 x64 Windows 드라이버에서 결정적 CPU0 선점을 활성화합니다. 생략하면 협력 방식과 유휴 시에만 진행하는 가상 시간을 유지합니다. 두 필드는 양의 정수이고 곱은 `uint64_t` 범위여야 합니다. 빈 객체는 아래 기본값을 사용합니다.

```json
{
  "scheduling": {
    "quantum_instructions": 1024,
    "instruction_time_100ns": 1
  }
}
```

`quantum_instructions`는 스레드에 허용하는 기계 명령 시도 횟수입니다. `instruction_time_100ns`는 시도별 가상 시간이며 하드웨어 속도가 아닙니다. 모델 API와 명령 트랜잭션을 완료한 뒤 전환합니다. 이벤트 경계는 남은 퀀텀을 초기화하지 않습니다. 보고서는 `configuration.scheduling`에 정책을 기록합니다.

실행 가능한 연속 실행 상태, 새 작업 항목과 시스템 스레드는 공통 준비 순서를 사용합니다. 중첩 호출과 SEH는 소속 스레드의 퀀텀을 공유합니다. 전체 CPU 상태, 논리 스레드 식별자, APC 상태, 유효 IRQL 및 프로세스 매핑을 보존합니다. PASSIVE/APC에서 선점할 수 있고 DISPATCH 이상에서는 스레드 전환을 차단합니다. 임계 및 guarded 영역은 APC를 비활성화하지만 스레드 선점은 막지 않습니다.

명령 실행 중에도 마감 시간 순서대로 타이머와 DMA가 진행됩니다. 취소는 취소 잠금의 사용 가능 여부를 확인하고 WDM dispatch 반환도 기다립니다. 페이지 가능한 provider 완료, 전원 정책과 PoFx 서비스는 PASSIVE 경계를 기다리며 원래 마감 시간과 실제 서비스 시각을 구분합니다. 시계가 생성한 독립 콜백과 차단 호출자의 같은 스레드 PoFx 콜백은 각 소유권을 유지합니다. 대기 결과는 기한에 확정되며 이후 타이머 재설정이나 이벤트 신호로 바뀌지 않습니다. 한 명령 시도가 두 기한을 모두 지나는 경우에도 같습니다.

Windows 우선순위 클래스와 동적 상승, OS 모델의 병렬 CPU, 임의 인터럽트 중첩, APC 전달, Windows ring3 스레드 생성과 스케줄링은 아직 구현하지 않습니다. CPU 병렬 실행은 별도 기능입니다. 직접 컴파일한 드라이버로 짧은 퀀텀, 부동소수점/GS 상태, 시간 대기, 교차 프로세스 연결, 취소 및 PoFx 연속 실행을 검증합니다. ARM64 네이티브 OS 검증은 별도로 추적합니다.
