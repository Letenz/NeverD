# 패킹된 실행 파일 언패킹

`neverd unpack`은 패킹된 실행 파일이 자신의 주소 공간 안에 다시 만들어 내는 프로그램을 복구합니다. 입력을 유한한 게스트 프로세스로 실행하고, 스텁이 자신이 생성한 코드로 제어를 넘기는 지점을 관찰하여, 그 시점의 이미지를 같은 컨테이너 형식의 새 파일로 기록합니다. 가상화 해제는 하지 않습니다. 보호 도구가 가상화한 함수는 가상화된 채로 남습니다. 빌드에는 `NEVERD_ENABLE_CPU_EMULATION=ON`이 필요합니다.

## 지원하는 입력

컨테이너 형식은 파일을 검증하고 재구성하는 방법을, 명령어 집합은 전이를 판정하는 방법을 정하며, 둘이 함께 게스트 프로세스 프로필을 정합니다. 이 표에 없는 입력은 어떤 코드도 실행되기 전에 이름과 함께 거부됩니다.

| 컨테이너 (`format`) | 명령어 집합 | 게스트 프로필 | 진입점 근거 |
| --- | --- | --- | --- |
| PE32+ (`pe64`) | x86-64 | [`windows-pe64-v1`](process-emulation.md) | 실행 중 관찰 |
| PE32+ (`pe64`) | ARM64 | [`windows-pe64-v1`](process-emulation.md) | 실행 중 관찰 |

## 사용법

```bash
neverd unpack packed.exe -o unpacked.exe
neverd unpack packed.exe -o unpacked.exe \
  --options='{"backend":"unicorn","instruction_limit":400000000,"transfer":2}'
```

이 명령은 JSON 보고서 하나를 출력합니다. 종료 코드 0은 이미지가 기록되었음을, 3은 진입점이 채택되기 전에 유한 실행이 끝났음을(`outcome`은 `no_entry`이며 아무것도 기록되지 않음), 1은 입력이나 옵션이 잘못되었거나 준비에 실패했음을 뜻합니다. 보고서에는 실제로 실행된 `format`, `architecture`, `profile`이 기재됩니다. C 진입점은 `neverd_unpack_json`이고 Python은 `Session.unpack`을 제공합니다. 옵션은 [프로세스 옵션](process-emulation.md)에 `transfer`를 더한 것입니다. 스텁에 더 많은 자원이 필요한 항목은 기본값이 다릅니다. 명령 100000000개, 600초, 512 MiB이며 `windows.defer_unmodeled`가 켜져 있습니다.

## 진입점을 정하는 방법

0세대는 게스트 로더가 매핑한 이미지입니다. 전이는 이전에 실행하던 코드보다 새로운 코드의 실행 시작을 뜻합니다. `transfers`는 RVA, `generation`, 스택 일치 여부(`stack_balanced`), 주 프로그램 진입 호출에 속하는지(`program_invocation`)를 기록합니다. 그 호출 전에는 첫 초기화 함수의 스택과 비교합니다.

1. 기본 진입점은 `stack_balanced`와 `program_invocation`을 모두 요구합니다. 스텁이 주 진입 호출의 스택을 반환했음을 뜻하며 `entry_source`는 `transfer`입니다.
2. OS가 호출한 TLS 및 DLL 콜백은 기록되지만 스택이 같아도 기본 진입점이 될 수 없습니다. 깊은 게스트 호출도 계속 실행합니다. 콜백을 건너뛰거나 스텁 서명으로 진입점을 예측하지 않습니다.
3. `transfer`는 초기화 콜백과 단계별 전이를 포함해 목록의 위치로 명시적으로 선택합니다.

컴파일러 시작 코드의 형태로 진입점을 추측하지 않습니다. 실행이 먼저 멈추면 `no_entry`와 프로세스의 `stop_reason`이 보고됩니다.

## 재구성된 이미지

섹션은 RVA, 관찰한 메모리(이미 실행한 초기화의 효과 포함), 페이지 권한을 유지합니다. 새 `.neverd` 섹션에 가져오기 디렉터리와 내보내기 호출과 주소 로드 복구용 새 IAT 셀을 두어 기존의 0으로 채운 저장소를 보존합니다. `imports`의 `origin`은 입력에서 바인딩한 `static`과 게스트가 쓰거나 복구 과정에서 추가한 `runtime`을 구분합니다. 생성된 내용의 재배치는 관찰하지 않았으므로 관찰한 기준 주소에 고정하고 재배치 디렉터리를 제거하여 `IMAGE_FILE_RELOCS_STRIPPED`를 설정합니다.

기존 런타임 IAT 후보는 동일 제공 모듈의 연속된 내보내기 포인터 배열이어야 하며 원래 섹션 안에 온전한 0 종료 셀이 있어야 합니다. 인접 제공 모듈의 종료 셀은 사용할 수 없습니다.

TLS 디렉터리는 로더의 할당 식별 정보, 완전히 종료된 콜백 목록, 생성 코드에 대한 관찰된 호출로 복구합니다. 후보가 여러 개면 명시적으로 실패합니다. 보호기 이름이나 전용 바이트는 사용하지 않습니다. 디렉터리를 선택할 때 생성된 콜백의 실행 증거를 완료된 로더 초기화 증거보다 우선합니다.

`materialized_tls_callbacks`는 주 프로그램 진입 호출을 캡처하기 전에 OS의 프로세스 연결 호출에서 정상 반환한 주 이미지 TLS 콜백 수입니다. 메모리 효과는 이미 스냅샷에 있습니다. 새 `.neverd` 섹션의 어댑터는 반복되는 프로세스 연결 호출만 생략하고 다른 알림은 원래 콜백으로 꼬리 호출합니다. 디렉터리, 콜백 테이블, 어댑터는 새 저장 공간을 사용하며 원래 바이트를 보존합니다. 어댑터가 있으면 실행 가능하며 새 IAT 셀이 필요할 때만 쓰기 가능합니다. 이 완료 증거가 없는 게스트 내부 콜백은 원래 동작을 유지합니다. 프로세스 연결 시 주 스레드 TLS가 템플릿과 다르면 첫 어댑터가 캡처한 데이터도 복원합니다. 실행 중 TLS 증거가 없거나 크기가 맞지 않으면 명시적으로 실패합니다. 원래 템플릿은 이후 스레드용으로 유지하며 다른 알림에서는 캡처한 블록을 복원하지 않습니다.

지연 로딩은 앞선 초기화 함수가 코드를 생성할 0으로 채운 메모리를 실행 가능한 콜백이나 진입 대상으로 허용합니다. 콜백 배열과 TLS 할당 메타데이터는 검증된 파일 내용이 필요하며 일반 엄격 로딩은 파일 뒷받침 검사를 유지합니다. OS 모델은 호출 소속을 제공하고 호출 준비 또는 일시 중단된 호출자 복원 시 관찰자에게 알립니다. 이 경계에서 전이 감시를 다시 설정하여 콜백과 생성된 진입점이 같은 페이지인 경우도 처리합니다.

`import_repair`는 진입점 캡처 후 두 번의 추가 제한 실행을 다룹니다. 먼저 내보내기 호출을 찾고, 다음 실행에서 도우미 상태를 관찰합니다. 각 실행에는 별도의 프로세스 한도가 적용됩니다. 명령 및 이벤트 수는 포화 합이며 `stop_reason`과 진단은 마지막 실행을 나타내고 호출 수는 검색 단계만 셉니다. 복귀 주소가 없으면 상태 관찰을 생략합니다. 내보내기 식별이 충돌하는 위치는 수정하지 않습니다. 실행한 경로만 다루므로 `unpacked`는 모든 가져오기나 프로그램 실행 성공을 보장하지 않습니다.

가져오기 바인딩 순서가 바뀌면 내보내기 주소도 달라질 수 있습니다. 복구는 증명 실행의 식별 정보를 보존하고 진입점 이후에 확인한 내보내기도 관찰합니다. 다른 실행의 주소는 재작성 근거가 될 수 없습니다.

검색은 모델링된 호출 로그에만 의존하지 않고 실행을 중단시키는 미모델링 내보내기까지 디스패치를 관찰합니다. ABI 반환 위치를 읽을 수 없으면 도우미 증거로 사용할 수 없습니다. 불투명 내보내기의 순수 호출을 복구해도 명시적인 미지원 서비스 중단을 유지합니다.

실제 내보내기 호출의 복귀 위치 앞 256바이트에서 최대 256개 시작 후보를 관찰합니다. GPR PUSH/POP이 앞설 수 있는 `CALL rel32`는 관찰 경계만 식별하며 CALL 뒤 바이트는 서명이 아닙니다. 6~8바이트 호출을 `call [rip+IAT]`로 바꾸려면 API 진입 시 반환 주소 하나만 추가되고 다른 레지스터(플래그와 SIMD 포함), 매핑과 영구 RAM이 같으며 앞선 OS 호출이 없어야 합니다. 선행 NOP으로 정확한 API 반환 주소를 유지합니다. 7~8바이트 구간이 알려진 내보내기를 GPR 하나에 반환하고 스택 균형과 같은 보존 조건을 만족하면 `mov r64, [rip+IAT]`로 바꿀 수 있습니다. 결과 레지스터는 상태 비교로 정하며 RSP를 제외한 모든 GPR과 R8-R15를 지원합니다. 8바이트 로드에는 후행 NOP을 남깁니다. 호출자 SP 아래 임시 공간만 제외하고 호출자 스택은 비교합니다. 이후 부작용, 미해결 또는 미완료 호출은 앞선 증거를 무효화합니다. 실제 실행 시작이 필요하며 앞 바이트를 REX로 추측하지 않고 같은 반환 주소의 겹치는 시작은 거부합니다. `observed_loads`와 `repaired_loads`는 주소 로드를 별도로 셉니다.

원래의 섹션 테이블, 임포트 디렉터리 배치, 재배치 테이블은 재구성되지 않습니다. 패커가 이를 메모리에 복원하지 않기 때문입니다.

## 식별

호환 필드 `packer.kind`와 `packer.evidence`는 `unidentified`와 빈 배열을 반환합니다. 보호기 레지스트리, 압축 헤더 분석, 스텁 서명을 제거했습니다. 기존 식별 API는 컨테이너만 검증합니다.

## 제한

EXE만 실행하며 DLL은 실행하지 않습니다. 검사 실행은 명령 단위입니다. x64 Unicorn/KVM/WHP의 `direct-user-x64-v1`은 시간과 이벤트로 제한하고 명령 수를 세지 않습니다.  추적은 4 KiB 페이지 단위이며 같은 세대의 이미 실행한 페이지 안에서 수정된 코드는 전이로 보고하지 않습니다. 진입 전 초기화의 외부 상태는 새 프로세스로 옮기지 못할 수 있고 TLS 콜백 재실행에는 부작용이 있을 수 있습니다. 모델링하지 않은 API에서 명시적으로 중단합니다. 복구 범위는 검증된 6~8바이트 x64 호출 구간과 7~8바이트 주소 로드이며 다른 형식과 미실행 경로는 미해결입니다. 가상화 코드는 유지됩니다.

## 검증

`NeverDUnpackTests`는 컨테이너, 안전한 IAT 할당, 충돌 근거와 TLS 거부를 검사합니다. `NeverDUnpackExecutionTests`는 Unicorn/KVM/WHP의 공통 경로로 UPX NRV2B/NRV2D/NRV2E/LZMA 및 CRT를 검사하고 독립 링크 프로그램 자체의 초기화 이후 섹션과 비교하며 사용 가능한 백엔드의 출력 일치를 요구합니다. `UnpackGeneratedTests.cpp`는 독립 x86-64/ARM64 프로그램으로 전이, 단계적 로딩, 가져오기 복구 및 x64 Unicorn/KVM/WHP 직접 실행을 검사합니다. 네이티브 CI 필수 사례의 건너뛰기는 실패입니다. `NeverDUnpackPublicTests`는 C ABI와 CLI를 다룹니다. `unittests/unpack/fixtures/Makefile`로 UPX 표본을 다시 생성합니다.
