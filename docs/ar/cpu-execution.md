# تنفيذ CPU والاستعلام عن القدرات

تنفيذ CPU مستقل عن نظام التشغيل الضيف ومحمّل الصور واتفاقية الاستدعاء. فعّل `NEVERD_ENABLE_CPU_EMULATION` لبنائه وحده، أو `NEVERD_ENABLE_DRIVER_EMULATION` لتضمين بيئة برامج تشغيل Windows. يشرح [دليل البنية](architecture.md) الملكية واختيار المحرك والقيود الحالية.

## الإعداد

تستخدم واجهة [`ExecutionConfiguration`](../../include/neverd/emulation/ExecutionConfiguration.h) العامة مصنع CPU وتقرير القدرات نفسيهما. تُفحص المتطلبات قبل تخصيص CPU أو ربط مساحة العناوين؛ القيم المحذوفة تستخدم ملف العقد الثابت، والقيم الصريحة غير المدعومة تفشل.

| حقل JSON | الافتراضي | المعنى |
|---|---|---|
| `backend` | `auto` | `auto` أو `unicorn` أو `kvm` أو `whp` |
| `contract` | `software-cpu-v1` | دلالات تنفيذ ذات إصدار |
| `architecture` | `x86_64` | `x86_64` أو `aarch64` |
| `privilege` | ملف العقد | `flat` أو `supervisor` أو `user`، ويجب أن يطابق العقد |
| `virtual_address_bits` | ملف العقد | العقود المفحوصة 48 بت؛ الملفات المسطحة توفر فضاء ربط مباشر بعرض 64 بت |
| `page_size` | 4096 | حجم وحدة ربط الضيف؛ القيم الأخرى مرفوضة |
| `required_features` | `[]` | أسماء الميزات المطلوبة من [`ExecutionConfiguration.def`](../../include/neverd/emulation/ExecutionConfiguration.def) |

يقبل `driver-strict` x64، ويقبل `software-cpu-v1` x64 وARM64. يتطلب `checked-x64-v1` و`checked-aarch64-v1` المعمارية المسماة وينفذان بامتياز المشرف. ينفذ `checked-user-x64-v1` و`checked-user-aarch64-v1` مجموعة التعليمات المحدودة الخاصة بالعقد عند CPL3 وEL0 مع عزل MMU وطلبات خدمة صريحة. يدعمان Unicorn وKVM/WHP المطابقين للمضيف؛ ويتبع `auto` اختيار المضيف. الملفات المسطحة لا تضمن عزل MMU أو نمط عناوين عتادي بعرض 64 بت. يرفض ملف ARM64 المفحوص FP/SIMD؛ أما x64 فيقبل عائلات محدودة موضحة أدناه. يضيف ملف x64 للمشرف معاملات MMIO محدودة وقراءات سلاسل محضرة؛ ملفات المستخدم ترفض تعيين الأجهزة. تظل منافذ I/O ومتطلبات CPU المتوازية مرفوضة في جميع الملفات المفحوصة. لا تعلن `service_traps` إلا ملفات المستخدم، وهي حد اعتراض موصوف أدناه.

يتطلب تنفيذ المستخدم `UserAccessible` إضافة إلى `Read` أو `Write` أو `Execute` المناسب على **كل** صفحة مرتبطة. الربوط الحالية افتراضياً للمشرف؛ والاسماء المستعارة لها صلاحيات مستقلة حتى إن شاركت البايتات. `UserAccessible` وحده لا يمنح وصولاً. عمليات المضيف الموثوقة وCPUs المشرفة تستخدم RWX. مثال:

```cpp
Configuration.Contract = ExecutionContract::CheckedUserX64;
Configuration.Privilege = ExecutionPrivilege::User;
auto CPU = llvm::cantFail(createExecutionBackend(Configuration, Space)).CPU;
llvm::cantFail(CPU->map(Code, 4096, Read | Write | Execute | UserAccessible));
```

الامتياز ثابت وفق العقد؛ استعادة السياق وربط مساحة العناوين لا يغيرانه، وكتابة محددات مقاطع x64 لا ترفع الامتياز. تحتفظ أعطال البيانات القابلة للاسترداد بالتعليمة والسجلات الأصلية إلى أن يعالجها مالكها. يفحص `canAccess` بتات الصلاحية المطلوبة بالضبط؛ أضف `UserAccessible` للاستعلام عن رؤية المستخدم. ويفحص `executable` صلاحيات CPU المختار. إسقاطات جداول الصفحات خاصة بكل CPU، ولا تتيح جداول ضيف قابلة للتعديل أو واجهة لتبديل الامتياز؛ وفي ARM64 تصبح الصفحات المتاحة للمستخدم غير قابلة للتنفيذ عند EL1.

الحقول المجهولة أو الفارغة، والأسماء أو العروض الرقمية غير الصالحة، والميزات المكررة والتركيبات غير المدعومة تفشل. حد الإدخال 64 KiB وتبقى مصانع CPU القديمة وخيارات C الخاصة ببرامج التشغيل متوافقة.

## الاستعلام دون تنفيذ حمل

```bash
neverd cpu-capabilities
neverd cpu-capabilities \
  --configuration='{"contract":"checked-aarch64-v1","architecture":"aarch64"}' \
  --probe-host
```

إصدار المخطط 1. يفصل التقرير بين `requested_configuration` قبل ملء الافتراضيات، و`configuration` بعد التطبيع واختيار المحرك، و`capabilities` الدلالية الثابتة، و`build` لدعم المحول وتوافق ABI، و`host` (يكون null ما لم يطلب `--probe-host`). يبدأ الفحص CPU مؤقتاً فوق RAM خاصة؛ وهو يثبت إمكان التهيئة فقط، لا صلاحية حمل عمل أو تنفيذ ARM64 أصلي. قد يتغير التوفر بعد الاستعلام، ولا يجري التحويل بصمت إلى محرك بديل. يرجع CLI صفر لتقرير صالح حتى إن كان المحرك غير متاح، وواحداً لإعداد أو استعلام غير صالح.

## حدود SDK وC++

تقبل [`neverd_cpu_capabilities_json`](../../include/neverd/sdk/NeverDCAPICPU.h) جلسة قائمة وإعداداً اختيارياً و`ProbeHost` يساوي 0 أو 1؛ ولا يتطلب ملفاً محملاً. حرر النتيجة عبر `neverd_free_string`، ويشير NULL إلى خطأ في `neverd_last_error`. يبقى الرمز متاحاً في البناء المعطل لـCPU ويبلغ عن التعطيل صراحة. تعرض إضافات Python التقرير عبر `session.cpu_capabilities(...)`. تتيح واجهة C++ فصل `executionCapabilities` و`resolveExecutionConfiguration` و`queryExecutionBackendBuild` و`probeExecutionBackend`؛ ويربط `createExecutionBackend` CPU بمساحة قائمة أو ينشئ RAM ومساحة افتراضيتين.

## نتائج CPU والميزانيات

يعيد `CPU.runUntilExit(PC, TimeoutMicroseconds)` نتيجة [`ExecutionExit`](../../include/neverd/emulation/ExecutionExit.h) ذات نوع صريح. أخطاء الإعداد تسبق التنفيذ وتعيد `llvm::Error`؛ وبعد بدئه تُسجل أسباب الإيقاف والمهلة وطلب الخدمة والعطل القابل للاسترداد وفخ الضيف والعملية غير المدعومة وأعطال الجهاز/المحرك والتوقف غير المفسر. تتقدم أعطال CPU/الجهاز/الخلفية على طلب الإيقاف أو المهلة المتزامن، مع الاحتفاظ بالوقائع والتفاصيل. يجب أن تكون المهلة موجبة وقابلة للتمثيل ضمن المدة والموعد المطلق، وإلا يفشل الاستدعاء قبل تغيير CPU أو الملاحظات. استخدم ميزانية منتهية لكل تشغيل؛ لا تفسر صفراً بأنه تشغيل غير محدود. الحد زمني تعاوني وليس ضماناً حائطياً. النتيجة لا تستهلك عطلاً قابلاً للاسترداد؛ على مالك نظام التشغيل أخذه وتركيب انتقال استثناء صالح قبل الاستئناف. تبقى واجهات `run` و`fault` و`timedOut` القديمة، لكن تطبيقات CPU الخارجية التي لا تنفذ الحد الجديد ترفضه.

## طلبات الخدمة

يعترض ملف المستخدم x64 ترميز `SYSCALL` الدقيق بلا بادئة، ويعترض ARM64 `SVC #imm16`. تبقى `SYSENTER` و`INT` و`HVC` و`BRK` وغيرها غير مدعومة. يعمل مراقب التعليمات أولاً؛ وإذا لم يوقف التنفيذ أو يفشل، يعيد CPU `ExecutionExitKind::ServiceRequest` **قبل** التعليمة أو المحرك، مع نوعها و`PC` و`NextPC` ووسيط SVC. لا تتغير السجلات أو الأعلام أو المكدس أو الامتياز؛ لا تحدث آثار SYSCALL المعمارية على RCX/R11، ولا انتقال استثناء ARM64. وسيط SVC ليس رقماً عاماً للخدمة.

يبقى الطلب معلقاً ويمنع التنفيذ والتعديل وربط المساحة والتقاط السياق أو استعادته إلى أن يستهلكه المالك مرة واحدة بواسطة `takeServiceRequest()` أثناء التوقف. على مالك نظام التشغيل فك ABI واختيار النتيجة والسجلات وPC أو انتقال الاستثناء صراحة؛ الخدمة غير المدعومة تفشل هناك. إعادة التشغيل عند PC الأصلي تنتج طلباً آخر، ولا يصطنع النظام NOP أو نجاحاً. طلب الخدمة يتقدم على الإيقاف والمهلة المتزامنين، لكن فشل الضيف أو المحرك أعلى أولوية. توقف CPU أو HLT أو فخ أو مهلة لا يثبت نجاح حمل العمل. راجع [ملف Linux للعملية](process-emulation.md)؛ إنه نموذج منفصل وخدماته خاصة بنظام التشغيل، لا دليل على Windows أو Android أو Darwin. التنفيذ الأصلي على Windows وARM64 ما زال يحتاج تحققاً وقت التشغيل.

## امتدادات x64 وحالة التنفيذ الأصلي

يقبل ملف x64 المفحوص تحريكات ومنطق SSE/SSE2 القديمة، و`MOVLHPS`/`MOVHLPS`، والأشكال العددية المقنّعة `CVTTSS2SI`/`CVTTSD2SI`/`SUBSS`/`SUBSD`. يحفظ MXCSR الأعلام المتراكمة والتقريب وFTZ؛ ويرفض DAZ والاستثناءات غير المقنّعة. يظل FP/SIMD مرفوضاً في ملف ARM64 المفحوص. تُزامن واجهات KVM/WHP سجلات XMM الستة عشر وMXCSR؛ رفض الترميز غير المدرج أو تراكيبه غير المدعومة يستمر وفق قائمة التعليمات المرجعية.

يقبل x64 المفحوص أيضاً الأشكال القديمة المقنّعة `SS` و`SD` و`PS` و`PD` للتعليمات `ADD` و`SUB` و`MUL` و`DIV` و`SQRT` و`MIN` و`MAX`. يوحّد `X64SSEInstructions.def` عروض المعاملات والمحاذاة وقواعد القبول. يقارن `MaskedSSEArithmeticMatchesIndependentHostExecution` أشكال السجلات وRAM بمرجع مستقل على CPU المضيف، شاملاً أوضاع التقريب الأربعة وFTZ والأصفار الموقّعة والمدخلات دون الطبيعية وNaN. ويتحقق `SSEMemoryObserverStopsBeforeResultAndStatusChanges` من التوقف قبل الآثار. تبقى DAZ والاستثناءات غير المقنّعة وx87 وAVX غير مقبولة.

يمتد مؤشر الخيط إلى FS/GS في x64 و`TPIDR_EL0` في ARM64 عبر ترميزات `MRS`/`MSR` الدقيقة. تحفظ النقلات الأصلية والحالات الملتقطة هذه القيم مستقلة عن الذاكرة؛ وهذا لا ينشئ خيوط OS ولا يخصص كتل TLS. يدعم مشرف x64 معاملات MMIO العددية المحاذاة بعرض 1/2/4 بايت، وعنصر MOVS واحداً لكل حد استئناف. قراءة الجهاز تتطلب معاينة محضرة بلا آثار، ثم اعتماداً مرة واحدة؛ أجهزة Windows ذات سجلات المحاكاة توفر ذلك. عمليات RMW وMMIO الأوسع وI/O المنافذ تظل مرفوضة.

تفحص KVM وWHP طلب الإيقاف أثناء دخول أصلي نشط وتنتظران تأكيد الإلغاء قبل تحرير الموارد. يستخدم KVM خيط تنفيذ خاصاً وإشارة realtime مؤقتة؛ يجب ألا تكون الإشارة المختارة متجاهلة أثناء الدخول. لا يغير ذلك أقنعة الإشارات أو handlers الخاصة بالمستدعي. إذا كان تقدم الضيف غير مؤكد فالإلغاء فشل نهائي، ولا توجد مهلة حائطية مضمونة.

## الاستثناءات المتزامنة الأصلية في x64

تستخدم تعليمات `DIV`/`IDIV` في checked x64 نتائج المعالج الحقيقية و`#DE`. يعتمد KVM على IDT/IST خاصة بالمشرف، ويستخدم WHP خريطة اعتراض صريحة؛ يُحتفظ بالسياق الأصلي وأكواد الخطأ المتاحة بصورة مستقلة عن أخطاء النقل. يستهلك نموذج نظام التشغيل الحدث القابل للاستعادة قبل تثبيت سياق المتابعة. يحوّل نموذج برامج تشغيل Windows القسمة على صفر وفيض خارج القسمة إلى `STATUS_INTEGER_DIVIDE_BY_ZERO` مع تنفيذ مرشحات SEH و`__finally` وإعادة المحاولة فعليًا. يُبنى `NeverDX64ExceptionTests` دون Unicorn، ويتحقق `DriverWDMCPUException` من أمثلة WDK الأصلية. تُتخطى مضيفات WHP/ARM64 غير المتاحة صراحةً.

## آثار RAM المرحلية

يحتفظ `RAMTransaction` فقط باتحاد نطاقات الكتابة الفيزيائية المعلنة للتعليمة وتحت قفل التنفيذ. تُستعاد الذاكرة الأصلية قبل مراقبي النتائج؛ الإلغاء وفشل النقل واستثناءات المراقب لا تنشر RAM أو سجلات جزئية. تحتفظ أخطاء المعالج بحالة الاستثناء المعمارية بعد تراجع RAM. تستخدم كتابات ARM64 المفردة والمزدوجة نفس السلطة. تنفذ x64 تعليمات `XCHG` و`XADD` و`CMPXCHG` بعروض 8/16/32/64 بت، مع محاذاة طبيعية للأشكال المقفلة أو ذات القفل الضمني. تقارن اختبارات `NeverDRAMTransactionTests` النتائج بمعالج المضيف وتختبر التراجع والمرادفات والصلاحيات؛ تُتخطى المنصات غير المتاحة صراحةً. تبقى الأجهزة وSMP المتوازي خارج هذا العقد، ولا تستعيد لقطات CPU ذاكرة سبق اعتمادها.

## حالة x87 الكاملة

تملك `NeverDEmulationArch` عقود ISA وجداول الصفحات وتنسيق FP المشترك بين النقل الأصلي وUnicorn. تحفظ سياقات x64 التحكم والحالة وTOP والوسوم الفيزيائية ورمز العملية ومؤشرات التعليمات/البيانات وثمانية سجلات بطول 80 بت. تستخدم `FP0`–`FP7` نوع `RegisterValue` ويرفض الوصول العددي الاقتطاع. يمثل `FPTag` قناع السجلات الفيزيائية غير الفارغة. تتحقق `NeverDX64FPTests` من كل قيم TOP والعمليات الدقيقة بمقارنتها مع FXSAVE/FXRSTOR للمضيف واستعادة السياق. لا يتيح ذلك تعليمات x87 ضمن checked ولا يثبت جميع حالات التقريب. يجري تجاوز المضيفات الأصلية غير المتاحة صراحةً.

يدعم `driver-strict` كلاً من KVM على مضيف Linux x64 المطابق وWHP على Windows x64 المطابق؛ يختار `auto` هذا النقل الأصلي، وتستخدم ISA المختلفة Unicorn. يحتفظ Unicorn الصريح وAPI V1 السابق بالملف البرمجي المحمول. يتحقق التنفيذ الأصلي من العناوين القانونية والآثار قبل الدخول؛ ويفشل العتاد غير المتاح دون تراجع. التعليمات وسلوك OS غير المدعومين أخطاء صريحة. لا تزال أدلة التشغيل الأصلي ARM64/WHP ناقصة، ولا تثبت هذه القدرة توافق أي برنامج تشغيل أو Android/Darwin.

يمكن الاستعلام عن الملف المحدد باستخدام `executionCapabilities(Contract, ISA, Backend)`. يصف `NativeLegacyX64` التنفيذ الأصلي لبرامج تشغيل x64. تتحقق اختبارات `NeverDNativeDriverTests` من المجموعة الحالية ويمكن تشغيلها أيضاً في بناء دون Unicorn.

تتبع قراءة حالة الأعداد الصحيحة الأصلية في ARM64 جهة ISA موحدة. يسرد `AArch64GeneralState.def` السجلات X0–X30 وSP وPC وNZCV وTPIDR_EL0؛ ويجمع `captureAArch64GeneralState` جميع القراءات قبل تطبيع NZCV ونشر النتيجة الكاملة. يشترك KVM وWHP في هذه الدالة. يحافظ فشل القراءة على كل حالة الإدخال، وتبقى الامتيازات والمتجهات والسجلات غير المنقولة دون تغيير. لا تُضاف تعليمات FP/SIMD أصلية مسموحة.

يمكن لعمليات RAM المفحوصة العددية والمزدوجة في ARM64 عبور صفحات ذات تخزين منفصل أو أسماء بديلة عند EL0 وEL1. تحسب طبقة ISA نطاقات المعاملات؛ وتتحقق مساحة العناوين المشتركة من كل صفحة قبل الدخول وتبلغ عن أول جزء يفشل. تثبت `RAMTransaction` البايتات المادية المعلنة بعد خطوة CPU كاملة. تحفظ الأعطال وإيقاف المراقب RAM والسجلات وتحديث العنوان. تستخدم `NeverDAArch64MemoryTests` الحالات المجمعة في `AArch64CrossPageCases.def`؛ ولا يضيف ذلك FP/SIMD أو تحميل برامج تشغيل Windows ARM64.

يستخدم KVM x64/ARM64 المتحكم `KvmRunControl` لتحضير الحالة والدخول إلى `KVM_RUN` وقراءة الحالة على خيط vCPU خاص واحد. يُنفذ التحضير مرة واحدة قبل محاولات الإعادة بعد `EINTR`؛ ولا تُقرأ الحالة إلا بعد عودة ناجحة من دخول المضيف. تبقى دوال النقل المستعارة صالحة حتى تأكيد انتهاء الدخول. يظل فك ISA ومعاملات RAM وسياسة نظام التشغيل ومراقبو التنفيذ على الخيط المستدعي. يؤدي فشل التحضير إلى تجاوز الدخول والقراءة؛ ويمنع فشل القراءة أو الإلغاء نشر حالة الضيف. ينفذ `KvmAArch64Machine.cpp` أيضاً مداخل صيانة ترجمة العناوين وتحضير سجلات الضيف وإعداد التصحيح وقراءة السجلات الـ35 كلها على هذا الخيط. تشترك الصيانة وتنفيذ الضيف في مهلة واحدة للخطوة؛ ولا يطبق الخيط المستدعي `captureAArch64GeneralState` إلا بعد تأكيد اكتمال القراءة. لا تزال أدلة التنفيذ الأصلي ARM64 غير متوفرة.

يقارن KVM السجلات العامة وحالة FP/SSE الكاملة بآخر حالة تصحيح جرى تأكيد قراءتها وفق `X64HostRegisters.def` و`X64FPState.def`، ويعيد تثبيت المدخلات المتغيرة. تدخل كتابات المضيف واستعادة السياق في المقارنة؛ وتبطل الاستثناءات والإلغاء والفشل إعادة الاستخدام. يظل إعداد الخطوة الواحدة وقراءة الحالة العامة/FP الفعلية قائمين لكل تعليمة.

التنفيذ العتادي وحده لا يضمن زمناً إجمالياً أقل. يقوم التنفيذ الأصلي الحالي بفحص قبول التعليمة والمراقبة ونقل الحالة والخروج من VM لكل خطوة. قارن الصور والسيناريوهات الأصلية نفسها بميزانيات تعليمات وأحداث متطابقة، وأبلغ عن تطابق النتائج مع الأزمنة؛ وأدرج بدء CLI والتحميل عند قياس زمنه.

تستخدم عملية التقاط حالة checked ARM64 الآن حدّ نشر موحّدًا تملكه طبقة ISA. يلتقط KVM/WHP الحقول الـ35 في `AArch64GeneralState.def`، ويحافظ Unicorn على الحقول العددية العامة الـ39، بما فيها حالة الخيط والتحكم بالفاصلة العائمة الإضافية. تطبّق `captureAArch64ScalarState` العروض من `Registers.def` وتطبّع NZCV، ولا تنشر الحالة إلا بعد نجاح جميع القراءات. تبقى الصلاحية والمتجهات والحقول غير المنقولة دون تغيير. لا يجيز نقل الحالة هذا تعليمات FP/SIMD في checked ARM64.
