# تنفيذ CPU والاستعلام عن القدرات

تنفيذ CPU مستقل عن نظام التشغيل الضيف ومحمّل الصور واتفاقية الاستدعاء. فعّل `NEVERD_ENABLE_CPU_EMULATION` لبنائه وحده، أو `NEVERD_ENABLE_DRIVER_EMULATION` لتضمين بيئة برامج تشغيل Windows. يشرح [دليل البنية](architecture.md) الملكية واختيار المحرك والقيود الحالية.

تكون `NEVERD_ENABLE_SEMANTIC_TESTS` بقيمة `ON` افتراضياً، وتتحكم في مجموعة `unittests/semantic` وأهداف تشغيلها المجمعة. لبناء اختبارات CPU الأصلية دون Unicorn، أبقِ `BUILD_TESTING=ON` واضبط `NEVERD_ENABLE_SEMANTIC_TESTS=OFF` و`NEVERD_EMULATION_BACKEND_UNICORN=OFF`. تظل اختبارات KVM/WHP الأصلية متاحة، بما فيها إعداد Windows ARM64/MSVC مع ترويسات SDK المناسبة. لا يزال تفعيل Unicorn على Windows ARM64 يتطلب سلسلة أدوات ARM64 LLVM-MinGW. فصل البناء هذا لا يثبت تنفيذ ARM64 على عتاد أصلي.

## الإعداد

تستخدم واجهة [`ExecutionConfiguration`](../../include/neverd/emulation/ExecutionConfiguration.h) العامة مصنع CPU وتقرير القدرات نفسيهما. تُفحص المتطلبات قبل تخصيص CPU أو ربط مساحة العناوين؛ القيم المحذوفة تستخدم ملف العقد الثابت، والقيم الصريحة غير المدعومة تفشل.

| حقل JSON | الافتراضي | المعنى |
|---|---|---|
| `backend` | `auto` | `auto` أو `unicorn` أو `kvm` أو `whp` |
| `contract` | `software-cpu-v1` | دلالات تنفيذ ذات إصدار |
| `architecture` | `x86_64` | `x86_64` أو `aarch64` |
| `privilege` | ملف العقد | `flat` أو `supervisor` أو `user`، ويجب أن يطابق العقد |
| `virtual_address_bits` | ملف العقد | العقود المفحوصة 48 بت؛ الملفات المسطحة توفر فضاء ربط مباشر بعرض 64 بت |
| `page_size` | 4096 | حجم وحدة ربط الضيف؛ القيم الأخرى مرفوضة |
| `required_features` | `[]` | أسماء الميزات المطلوبة من [`ExecutionConfiguration.def`](../../include/neverd/emulation/ExecutionConfiguration.def) |

يقبل `driver-strict` x64، ويقبل `software-cpu-v1` x64 وARM64. يتطلب `checked-x64-v1` و`checked-aarch64-v1` المعمارية المسماة وينفذان بامتياز المشرف. ينفذ `checked-user-x64-v1` و`checked-user-aarch64-v1` مجموعة التعليمات المحدودة الخاصة بالعقد عند CPL3 وEL0 مع عزل MMU وطلبات خدمة صريحة. يدعمان Unicorn وKVM/WHP المطابقين للمضيف؛ ويتبع `auto` اختيار المضيف. الملفات المسطحة لا تضمن عزل MMU أو نمط عناوين عتادي بعرض 64 بت. يقبل ARM64 وx64 المفحوصان عائلات FP/SIMD المحدودة الموضحة أدناه. يضيف ملف x64 للمشرف معاملات MMIO محدودة وقراءات سلاسل محضرة؛ ملفات المستخدم ترفض تعيين الأجهزة. تظل منافذ I/O ومتطلبات CPU المتوازية مرفوضة في جميع الملفات المفحوصة. لا تعلن `service_traps` إلا ملفات المستخدم، وهي حد اعتراض موصوف أدناه.

يتطلب تنفيذ المستخدم `UserAccessible` إضافة إلى `Read` أو `Write` أو `Execute` المناسب على **كل** صفحة مرتبطة. الربوط الحالية افتراضياً للمشرف؛ والاسماء المستعارة لها صلاحيات مستقلة حتى إن شاركت البايتات. `UserAccessible` وحده لا يمنح وصولاً. عمليات المضيف الموثوقة وCPUs المشرفة تستخدم RWX. مثال:

```cpp
Configuration.Contract = ExecutionContract::CheckedUserX64;
Configuration.Privilege = ExecutionPrivilege::User;
auto CPU = llvm::cantFail(createExecutionBackend(Configuration, Space)).CPU;
llvm::cantFail(CPU->map(Code, 4096, Read | Write | Execute | UserAccessible));
```

الامتياز ثابت وفق العقد؛ استعادة السياق وربط مساحة العناوين لا يغيرانه، وكتابة محددات مقاطع x64 لا ترفع الامتياز. تحتفظ أعطال البيانات القابلة للاسترداد بالتعليمة والسجلات الأصلية إلى أن يعالجها مالكها. يفحص `canAccess` بتات الصلاحية المطلوبة بالضبط؛ أضف `UserAccessible` للاستعلام عن رؤية المستخدم. ويفحص `executable` صلاحيات CPU المختار. إسقاطات جداول الصفحات خاصة بكل CPU، ولا تتيح جداول ضيف قابلة للتعديل أو واجهة لتبديل الامتياز؛ وفي ARM64 تصبح الصفحات المتاحة للمستخدم غير قابلة للتنفيذ عند EL1.

الحقول المجهولة أو الفارغة، والأسماء أو العروض الرقمية غير الصالحة، والميزات المكررة والتركيبات غير المدعومة تفشل. حد الإدخال 64 KiB وتبقى مصانع CPU القديمة وخيارات C الخاصة ببرامج التشغيل متوافقة.

## الاستعلام دون تنفيذ حمل

```bash
neverd cpu-capabilities
neverd cpu-capabilities \
  --configuration='{"contract":"checked-aarch64-v1","architecture":"aarch64"}' \
  --probe-host
```

إصدار المخطط 1. يفصل التقرير بين `requested_configuration` قبل ملء الافتراضيات، و`configuration` بعد التطبيع واختيار المحرك، و`capabilities` الدلالية الثابتة، و`build` لدعم المحول وتوافق ABI، و`host` (يكون null ما لم يطلب `--probe-host`). يبدأ الفحص CPU مؤقتاً فوق RAM خاصة؛ وهو يثبت إمكان التهيئة فقط، لا توافق أحمال العمل العامة. قد يتغير التوفر بعد الاستعلام، ولا يجري التحويل بصمت إلى محرك بديل. يرجع CLI صفر لتقرير صالح حتى إن كان المحرك غير متاح، وواحداً لإعداد أو استعلام غير صالح.

## حدود SDK وC++

تقبل [`neverd_cpu_capabilities_json`](../../include/neverd/sdk/NeverDCAPICPU.h) جلسة قائمة وإعداداً اختيارياً و`ProbeHost` يساوي 0 أو 1؛ ولا يتطلب ملفاً محملاً. حرر النتيجة عبر `neverd_free_string`، ويشير NULL إلى خطأ في `neverd_last_error`. يبقى الرمز متاحاً في البناء المعطل لـCPU ويبلغ عن التعطيل صراحة. تعرض إضافات Python التقرير عبر `session.cpu_capabilities(...)`. تتيح واجهة C++ فصل `executionCapabilities` و`resolveExecutionConfiguration` و`queryExecutionBackendBuild` و`probeExecutionBackend`؛ ويربط `createExecutionBackend` CPU بمساحة قائمة أو ينشئ RAM ومساحة افتراضيتين.

## نتائج CPU والميزانيات

يعيد `CPU.runUntilExit(PC, TimeoutMicroseconds)` نتيجة [`ExecutionExit`](../../include/neverd/emulation/ExecutionExit.h) ذات نوع صريح. أخطاء الإعداد تسبق التنفيذ وتعيد `llvm::Error`؛ وبعد بدئه تُسجل أسباب الإيقاف والمهلة وطلب الخدمة والعطل القابل للاسترداد وفخ الضيف والعملية غير المدعومة وأعطال الجهاز/المحرك والتوقف غير المفسر. تتقدم أعطال CPU/الجهاز/الخلفية على طلب الإيقاف أو المهلة المتزامن، مع الاحتفاظ بالوقائع والتفاصيل. يجب أن تكون المهلة موجبة وقابلة للتمثيل ضمن المدة والموعد المطلق، وإلا يفشل الاستدعاء قبل تغيير CPU أو الملاحظات. استخدم ميزانية منتهية لكل تشغيل؛ لا تفسر صفراً بأنه تشغيل غير محدود. الحد زمني تعاوني وليس ضماناً حائطياً. النتيجة لا تستهلك عطلاً قابلاً للاسترداد؛ على مالك نظام التشغيل أخذه وتركيب انتقال استثناء صالح قبل الاستئناف. تبقى واجهات `run` و`fault` و`timedOut` القديمة، لكن تطبيقات CPU الخارجية التي لا تنفذ الحد الجديد ترفضه.

## طلبات الخدمة

يعترض ملف المستخدم x64 ترميز `SYSCALL` الدقيق بلا بادئة، ويعترض ARM64 `SVC #imm16`. تبقى `SYSENTER` و`INT` و`HVC` و`BRK` وغيرها غير مدعومة. يعمل مراقب التعليمات أولاً؛ وإذا لم يوقف التنفيذ أو يفشل، يعيد CPU `ExecutionExitKind::ServiceRequest` **قبل** التعليمة أو المحرك، مع نوعها و`PC` و`NextPC` ووسيط SVC. لا تتغير السجلات أو الأعلام أو المكدس أو الامتياز؛ لا تحدث آثار SYSCALL المعمارية على RCX/R11، ولا انتقال استثناء ARM64. وسيط SVC ليس رقماً عاماً للخدمة.

يبقى الطلب معلقاً ويمنع التنفيذ والتعديل وربط المساحة والتقاط السياق أو استعادته إلى أن يستهلكه المالك مرة واحدة بواسطة `takeServiceRequest()` أثناء التوقف. على مالك نظام التشغيل فك ABI واختيار النتيجة والسجلات وPC أو انتقال الاستثناء صراحة؛ الخدمة غير المدعومة تفشل هناك. إعادة التشغيل عند PC الأصلي تنتج طلباً آخر، ولا يصطنع النظام NOP أو نجاحاً. طلب الخدمة يتقدم على الإيقاف والمهلة المتزامنين، لكن فشل الضيف أو المحرك أعلى أولوية. توقف CPU أو HLT أو فخ أو مهلة لا يثبت نجاح حمل العمل. راجع [ملف Linux للعملية](process-emulation.md)؛ إنه نموذج منفصل وخدماته خاصة بنظام التشغيل، لا دليل على Windows أو Android أو Darwin. التنفيذ الأصلي على Windows وARM64 ما زال يحتاج تحققاً وقت التشغيل.

## امتدادات x64 وحالة التنفيذ الأصلي

تمثل أوصاف تعليمات x64 المقنّعة الأساس المحمول. يضيف KVM/WHP قدرة `precise_simd_exceptions` إلى `driver-strict` و`checked-x64-v1` و`checked-user-x64-v1`: يتحقق فحص البدء الأصلي من `#XM` دقيق ومن مساري إعادة المحاولة قبل السماح بكتابة MXCSR غير المقنّع و`LDMXCSR` واستعادة Windows `CONTEXT`. يملك `ExecutionProfiles.def` الاختيار وتعرض `supportsSIMDExceptions` قدرة المثيل المحددة. يظل checked Unicorn مقنّعاً؛ ولا تضاف هنا قدرة استثناءات إلى ARM64 أو HVF.

ينقل KVM/WHP الأصلي على x64 أخطاء `#XM` الفعلية إلى C SEH في برنامج التشغيل عبر `X64SIMDException`. يحتفظ `CONTEXT` للأخطاء العتادية بسجلات XMM0–15 وMXCSR. تعمل المرشحات وfinally أثناء فك مكدس الاستثناء والمعالجات المختارة مع MXCSR `0x1f80` وعلم DF ممسوح. يستطيع المرشح السالب تعديل XMM و`CONTEXT.MxCsr` العلوي ضمن قناع CPU الضيف ثم إعادة التعليمة الأصلية؛ لا يتحكم `FltSave.MxCsr` في استعادة النواة. تحتفظ استثناءات API النموذجية بحقول الأعداد الصحيحة والتحكم؛ وتبقى تعديلات x87/AVX مرفوضة.

يقبل ملف x64 المفحوص تحريكات ومنطق SSE/SSE2 القديمة، و`MOVLHPS`/`MOVHLPS`، والأشكال العددية المقنّعة `CVTTSS2SI`/`CVTTSD2SI`/`SUBSS`/`SUBSD`. يحفظ MXCSR الأعلام المتراكمة والتقريب وFTZ؛ ويرفض التنفيذ المحمول الاستثناءات غير المقنّعة. تُزامن واجهات KVM/WHP سجلات XMM الستة عشر وMXCSR؛ رفض الترميز غير المدرج أو تراكيبه غير المدعومة يستمر وفق قائمة التعليمات المرجعية.

يقبل x64 المفحوص أيضاً الأشكال القديمة المقنّعة `SS` و`SD` و`PS` و`PD` للتعليمات `ADD` و`SUB` و`MUL` و`DIV` و`SQRT` و`MIN` و`MAX`. يوحّد `X64SSEInstructions.def` عروض المعاملات والمحاذاة وقواعد القبول. يقارن `MaskedSSEArithmeticMatchesIndependentHostExecution` أشكال السجلات وRAM بمرجع مستقل على CPU المضيف، شاملاً أوضاع التقريب الأربعة وFTZ والأصفار الموقّعة والمدخلات دون الطبيعية وNaN. ويتحقق `SSEMemoryObserverStopsBeforeResultAndStatusChanges` من التوقف قبل الآثار. تبقى x87 وAVX غير مقبولة.

في ملف التنفيذ البرمجي المحمول، يطبّق Unicorn وضع DAZ على القيمة التي تختارها التعليمات التقليدية `MINSS/MINSD/MINPS/MINPD` و`MAXSS/MAXSD/MAXPS/MAXPD`. يصبح المُدخل المختار دون الطبيعي صفراً بإشارته، مع الحفاظ على حمولة NaN وحالة MXCSR السابقة. يتحقق `test_x86_sse_minmax_daz` من صيغ السجلات وRAM والسجلات المتطابقة، مع تشغيل DAZ وإيقافه، وجميع أوضاع التقريب وFTZ والأعلام التراكمية.

تكتشف KVM/WHP قيمة `MXCSR_MASK` بتنفيذ خاص لـ `FXSAVE64` وتتحقق من DAZ بعملية حسابية على عدد دون طبيعي ذي إشارة. يقدم checked Unicorn قناعه البرمجي. تعرض `supportedControlBits` قناع CPU الثابت الذي تشترك فيه FX/XSAVE واللقطات وWindows CONTEXT. تصل تعليمات checked `LDMXCSR/STMXCSR` إلى m32 بدقة وتتحقق من كامل نطاق RAM وتحفظ الحالة عند الخطأ أو إلغاء المراقب. يؤدي تحميل البتات المحجوزة إلى #GP؛ ويرفض التنفيذ المحمول استثناءات SIMD غير المقنّعة. يتحقق `X64MXCSRTests.cpp` من التحكم وإعادة المحاولة، ويقارن `X64DAZData` جميع الصيغ الحسابية SSE المقبولة وعددها 28 بتعليمات المضيف الأصلية مع DAZ والتقريب وFTZ. لا يتوسع دعم DAZ في HVF.

يستخدم التحقق الأولي لـ x64 الأصلي ميزانية واحدة قدرها `5 s` تشمل تجهيز طبقة النقل عند التشغيل البارد وجميع خطوات الفحص. تبقى ميزانيات تنفيذ الضيف مستقلة. يوضح انقطاع التهيئة مرحلة التعليمة و`stop_requested` و`deadline_reached` مع الحفاظ على نوع الانقطاع وتشخيص النقل الأصلي. لا تُعاد المحاولة ولا تُقبل وحدة CPU لم يكتمل التحقق منها.

تُنفَّذ `PAUSE` (`F3 90`) عبر واجهة x64 المشتركة على KVM/WHP وUnicorn المقيّد، بما في ذلك عقد `driver-strict` الأصلي. يتحقق `X64PauseTests.cpp` من حفظ الحالة كاملة، والتوقف قبل التنفيذ، واستعادة السياق، ورفض `LOCK` غير الصالح، وانتهاء مهلة حلقات الانتظار النشط واستئنافها. لا تتولى هذه التعليمة الإرشادية للمعالج جدولة خيوط الضيف، ولا تضمن تأخيرًا محددًا.

تُنفَّذ `PUSHFQ` (`9C`) و`PUSHF` ذات 16 بت (`66 9C`) عبر KVM/WHP الأصليين وchecked Unicorn، بما في ذلك `driver-strict`. تزيل طبقة ISA المشتركة علم TF الداخلي للتنفيذ خطوة بخطوة من صورة المكدس قبل تثبيت معاملة RAM. تستخدم عنونة المكدس الضمنية RSP بالكامل؛ ويحدد ترتيب البادئات عرض المعامل. تحافظ صلاحيات النطاق الكامل وإيقافات المراقبين وإعادة المحاولة بعد الخطأ على الذرية. يغطي `X64PushFlagsTests.cpp` جميع تركيبات الأعلام المسموح بها وعددها 256، وتسعة ترميزات، والأسماء البديلة عبر الصفحات، وصلاحيات المستخدم، والإلغاء، واستعادة السياق.

تستعيد `POPFQ` (`9D`) و`POPF` ذات 16 بت (`66 9D`) الأعلام في طبقة ISA المشتركة لـ x64 على KVM وWHP وchecked Unicorn، بما فيها `driver-strict`. مع تثبيت IOPL عند الصفر يستطيع CPL0 تغيير IF، بينما يحافظ CPL3 على IF وIOPL. تُتجاهل البتات المحجوزة وVM/VIF/VIP ويُصفّر RF. تبقى التغييرات الفعلية في أعلام الضيف TF وNT وAC وID أو IOPL عند CPL0 غير مدعومة، وتُرفض قبل نشر الحالة. تسبق قراءة المكدس كاملةً التحديث الذري لـ FLAGS/RSP/RIP؛ ويحدّد RSP الكامل وترتيب البادئات الفعّال المعامل. يمكن أن يكون المكدس للقراءة فقط أو اسماً مستعاراً لذاكرة قابلة للتنفيذ. يمنع الإكمال المشترك مسح TF الداخلي لطبقة النقل. يقارن `X64PopFlagsTests.cpp` تعليمات CPL3 أصلية مستقلة ويفحص كل بت إدخال والأخطاء والمراقبين والتنفيذ الأصلي اللاحق.

يقبل checked x64 تعليمات `CLC/STC/CMC` و`LAHF/SAHF`. تنفذ طبقة النقل تعليمات الحمل، بينما تشترك عمليات AH في انتقال ISA واحد بين KVM وWHP وchecked Unicorn، بما فيه `driver-strict` الأصلي. تكتب LAHF خمسة أعلام وبتات ثابتة في AH، وتغير SAHF فقط CF/PF/AF/ZF/SF. تبقى OF/IF/DF والسجلات الأخرى سليمة. تحافظ البادئات المتجاهلة، بما فيها جميع قيم REX، على AH الضمني. يتحقق `X64StatusFlagsTests.cpp` من التعليمات الأصلية والحالة الكاملة والإلغاء والاستئناف. يحافظ مترجم Unicorn المثبت أيضاً على AH الضمني مع REX في الملف المحمول، ويرفض LOCK لهذه التعليمات الخمس قبل تغيير الحالة.

ينفذ checked x64 تعليمات `SHLD/SHRD` عبر KVM وWHP وUnicorn بوجهات 16/32/64 بت وعدّادات imm8 أو CL. يطبق القناع المعماري؛ ويرفض القيم غير المحددة الأكبر من 16 لمعاملات 16 بت قبل أي أثر. تستخدم وجهات RAM فحص قراءة وكتابة بالعرض الدقيق والمعاملة القائمة: مراقبة النتيجة قبل نشرها، والتراجع عن CPU والذاكرة عند الإلغاء. تبقى LOCK ومعاملات الأجهزة غير مدعومة.

تنفّذ `CMPXCHG8B` و`CMPXCHG16B` التعليمات الأصلية عبر KVM وWHP وchecked Unicorn في ملفات تشغيل برامج التشغيل والمستخدم. يلزم إذنا القراءة والكتابة سواء نجحت المقارنة أم فشلت، وتُصنَّف أخطاء الوصول كعمليات كتابة. تتحقق `CMPXCHG16B` من المحاذاة على 16 بايت قبل الوصول إلى الذاكرة وتبلغ عن `#GP(0)` عند المخالفة. تشترك ملاحظتا النتيجة في معاملة RAM واحدة؛ ولا ينشر التوقف أو الاستثناء في أي منهما تغييرات السجلات أو الذاكرة. يمكن لـ`CMPXCHG8B` دون قفل عبور حدود الصفحات، بينما تتطلب العمليات المقفلة المحاذاة الطبيعية. يقارن `X64WideAtomicTests.cpp` نتائج التعليمات الأصلية على المضيف والأخطاء الأصلية المباشرة، ويفحص الأسماء المستعارة والبادئات والعنونة والإصلاح والإلغاء. تنفّذ عيناتنا الأصلية لبرنامج تشغيل Windows وPE في ring3 كلا العرضين، وتنفّذ عينة WDK أيضاً `_InterlockedCompareExchange128`. يجب أن يدعم نموذج CPU التعليمة `CMPXCHG16B`.

## حالة x87 الكاملة

تملك `NeverDEmulationArch` عقود ISA وجداول الصفحات وتنسيق FP المشترك بين النقل الأصلي وUnicorn. تحفظ سياقات x64 التحكم والحالة وTOP والوسوم الفيزيائية ورمز العملية ومؤشرات التعليمات/البيانات وثمانية سجلات بطول 80 بت. تستخدم `FP0`–`FP7` نوع `RegisterValue` ويرفض الوصول العددي الاقتطاع. يمثل `FPTag` قناع السجلات الفيزيائية غير الفارغة. تتحقق `NeverDX64FPTests` من كل قيم TOP والعمليات الدقيقة بمقارنتها مع FXSAVE/FXRSTOR للمضيف واستعادة السياق. لا يتيح ذلك تعليمات x87 ضمن checked ولا يثبت جميع حالات التقريب. يجري تجاوز المضيفات الأصلية غير المتاحة صراحةً.

يدعم `driver-strict` كلاً من KVM على مضيف Linux x64 المطابق وWHP على Windows x64 المطابق؛ يختار `auto` هذا النقل الأصلي، وتستخدم ISA المختلفة Unicorn. يحتفظ Unicorn الصريح وAPI V1 السابق بالملف البرمجي المحمول. يتحقق التنفيذ الأصلي من العناوين القانونية والآثار قبل الدخول؛ ويفشل العتاد غير المتاح دون تراجع. التعليمات وسلوك OS غير المدعومين أخطاء صريحة. تجتاز CI الأصلية على Windows x64 مع تعطيل Unicorn جميع الفحوص الإلزامية البالغ عددها 359:‏ 131 فحص CPU و224 نتيجة لبرامج التشغيل من 26 صورة مدمجة و46 صورة WDK و40 حالة سيناريو عند العناوين المفضلة والمعاد تموضعها، إضافة إلى أربعة فحوص لحدود SEH ([`9d4c130c`](https://github.com/NeverSight/NeverD/actions/runs/36981864458)). لا تزال أدلة التشغيل الأصلي ARM64 ناقصة، ولا تثبت هذه القدرة توافق أي برنامج تشغيل أو Android/Darwin.

يمكن الاستعلام عن الملف المحدد باستخدام `executionCapabilities(Contract, ISA, Backend)`. يصف `NativeLegacyX64` التنفيذ الأصلي لبرامج تشغيل x64. تتحقق اختبارات `NeverDNativeDriverTests` من المجموعة الحالية ويمكن تشغيلها أيضاً في بناء دون Unicorn.

تستخدم checked ARM64 حدّاً موحداً للحالة الكاملة. يحدد `Registers.def` عدد 39 حقلاً عددياً و32 متجهاً بعرض 128 بت؛ يجمع `captureAArch64State` جميع القراءات ويطبق العروض وتطبيع NZCV قبل نشر واحد. تنقل Unicorn وKVM وWHP وHVF المجموعة نفسها، بما فيها TPIDR_EL0 وTPIDRRO_EL0 وTPIDR_EL1 وFPCR وFPSR. تفعّل الواجهات الأصلية FP/SIMD عبر CPACR_EL1. فشل أي قراءة أو إلغاء الدخول يحفظ كامل حالة المستدعي.

ينفذ بدء ARM64 KVM/WHP/HVF البرنامج الخاص `AArch64MachineProbe.def`: NOP وجمع FP32 بتقريب نحو اللانهاية الموجبة وجمع SIMD بمسارين. تقارن كل خطوة جميع الحقول العددية الـ39 والمتجهات الـ32، بما فيها TLS وNZCV وتصفير البتات العليا للنتيجة وحالة FPCR/FPSR المحفوظة والمتراكمة. يستخدم الفحص ذاكرة مراقب المشرف فقط وموعداً نهائياً إجمالياً واحداً. تثبت هذه الفحوص التهيئة المحدودة فقط. لا يزال التحقق من أحمال Linux ARM64 KVM وWindows ARM64 WHP معلقاً؛ نتائج macOS الأصلية مسجلة في [دليل HVF](macos-hvf.md). يتضمن البرنامج أيضًا توقيع عناوين العودة A/B والمصادقة عليها مع تعطيل المفاتيح، وأشكال BTI الأربعة على الصفحات غير المحمية.

ينفذ الفحص أيضًا `MRS CTR_EL0` مرتين، و`DC CVAU` و`DSB ISH` و`IC IVAU` و`ISB`، للتحقق من ثبات بنية الذاكرة المخبئية والحالة الكاملة. تقبل Checked EL0/EL1 التعليمات الأصلية وجميع خيارات DSB الأساسية المسماة وISB SY فقط. تأتي CTR من المعالج الافتراضي المختار وقد تختلف بين وسائل النقل. يجب أن تشير أهداف الصيانة إلى RAM عادية قابلة للقراءة بالصلاحيات الحالية، مع السماح بالعناوين غير المحاذاة والأسماء المستعارة؛ تُرفض الأهداف الأخرى باعتبارها غير مدعومة. لا تنشئ الصيانة أحداث مراقبة لقراءة البيانات أو كتابتها. يحافظ الإسقاط على اتساق تنفيذ التعليمات دون نمذجة محتويات مخابئ خاصة أو SMP عتادي متوازٍ. تختبر `NeverDAArch64CacheTests` الحالة ونهايات الصفحات للقراءة فقط والرفض والتوقف والسياقات والميزانيات وتحديث كود الضيف عبر أسماء RW/RX المستعارة الممتدة بين صفحتين. تُتخطى مضيفات KVM/WHP غير المتاحة صراحةً.

تنفذ تهيئة x64 الأصلية في KVM/WHP/HVF برنامج `X64MachineProbe.def` داخل صفحات supervisor خاصة. تشمل مهلة واحدة NOP وجمع FP32 بتقريب نحو اللانهاية الموجبة وجمع SIMD ذي مسارين وتحميل FS/GS وقراءة CS/SS/CR8؛ وتقارن كل خطوة الحالة الكاملة للقيم المفردة وXMM وسجلات x87 الفيزيائية وحقول التحكم. تتطلب اختبارات x64 وARM64 حق التنفيذ الحصري للذاكرة الفيزيائية. يملك `MemoryProjection` هوية التخزين المؤقت (ISA وفضاء العناوين وجيل التعيينات والامتياز ومتغير المراقب) وسجل الجذور المعتمدة لكل ISA. تبطل أدوات البناء التخزين المؤقت قبل إعادة الكتابة، فلا تعيد المحاولة الفاشلة استخدام جداول جزئية ولا يمرر المستدعي جذورًا قديمة. تثبت هذه الفحوص التهيئة المحدودة فقط. لا يزال التحقق من أحمال Linux ARM64 KVM وWindows ARM64 WHP معلقاً؛ نتائج macOS الأصلية مسجلة في [دليل HVF](macos-hvf.md).

يميّز مفكك XSAVE المشترك بين حالة SSE الابتدائية في التنسيق القياسي والمضغوط. عندما تكون XSTATE_BV[1] صفراً، يهيّئ كلاهما XMM؛ لكن القياسي يواصل قراءة MXCSR والتحقق منه، بينما يهيّئه المضغوط. يوفر `X64XsaveCases.def` تخطيطات مستقلة وبرامج XRSTOR أصلية للمضيف. يتحقق `X64XsaveTests.cpp` من ذرّية الرفض ويقارن التنسيقين بالتنفيذ الحقيقي مع حفظ حالة FP/SSE للجهة المستدعية. يُعلن صراحةً عن تخطي المقارنة عند غياب معمارية المضيف أو ميزة التعليمات المطلوبة.

يعلن `X64FPState.def` تخطيطات النقل المضغوطة لـ AVX وAVX-512 وCET_U/CET_S وAMX، بما فيها محاذاة المكونات إلى 64 بايت. يجب أن تمثل بيانات الامتداد الحاضرة الحالة الابتدائية المصفّرة؛ ولا تحدد المكونات الغائبة وحشو المحاذاة حالةً. تحدد بتات التخطيط الإزاحات، وتُرفض التخطيطات المجهولة والبيانات غير الابتدائية والأطوال الخاطئة قبل النشر. تغطي `CompactedOffsetsFollowLayoutRatherThanPresentBits` و`WideLayoutIgnoresAbsentComponentsAndAlignmentPadding` و`InitialCETComponentsDoNotHideFPState` و`InitialWideComponentsDoNotHideFPState` حزم WHP ذات 872 و10752 بايت. لا يتيح هذا النقل تنفيذ تعليمات هذه الامتدادات.

يكمل `WhpXsaveRegisters.def` حزم XSAVE الكاملة بسجلات تحكم x87/SSE المسماة. يكتب آخر رمز عملية ومؤشري التعليمة والبيانات صراحة ويقرؤها من المضيف. يمكن استكمال حقول الحزمة الصفرية، لكن تعارض البيانات غير الصفرية أو حقول التحكم المشتركة يفشل قبل نشر الحالة. يتحقق `NamedMetadataRestoresOmittedPacketFields` من الحقول المفقودة مع الاحتفاظ بكل بيانات FP.

تتبع الحقول الأصلية `FOP/FIP/FDP` قواعد حفظ واستعادة x87 للمضيف. قد يصفرها AMD عند غياب استثناء معلق غير مقنّع؛ وتحتفظ اللقطات بالقيم المرصودة. يهيئ `X64MachineProbe.def` واختبارات NOP والسياق الدقيقة استثناءً معلقاً متسقاً ليظل كل حقل صالحاً وتتم مقارنته دون إخفاء الفروق. يتحقق مرجع FXRSTOR64/FXSAVE64 في عملية المضيف من الحالتين؛ ولا تستبدل الخلفيات نتائج المضيف ببيانات الإدخال الوصفية.

يملك المرمز المشترك `encodeX64XsaveState` / `decodeX64XsaveState` حزم FP/SSE القياسية والمضغوطة ودوران TOP الفيزيائي والحالة الأولية للمكونات الغائبة والتحقق الذري. يستخدم WHP واجهات XSAVE الكاملة، مع تفضيل `WHvGetVirtualProcessorState` / `WHvSetVirtualProcessorState` وإبقاء واجهات XSAVE القديمة لمسار التوافق. لا تستبدل واجهة سجلات x87 الفردية القديمة الحزم الكاملة. تفشل صراحة المكونات الموسعة غير الابتدائية والرؤوس المشوهة وقيم التحكم غير الصالحة وقراءات الحالة المبتورة. تحفظ أخطاء تعيين WHP قيم HRESULT وGPA والحجم للتشخيص.

يقبل `CheckedX64Instructions.def` الضرب غير الموقّع `MUL` بعرض 8/16/32/64 بت والتعليمات `CBW/CWDE/CDQE/CWD/CDQ/CQO` عبر ناقل CPU الحالي. يستخدم `NeverDX64IntegerTests` ترميزات وقيماً متوقعة مستقلة من `X64IntegerCases.def` عند مستويَي الامتياز: حفظ أجزاء السجلات غير المتأثرة، والتمديد بالأصفار عند الكتابة بعرض 32 بت، ونصفي حاصل الضرب، ونتائج CF/OF المحددة، وثبات الأعلام عند تمديد الإشارة. يحتفظ الضرب في RAM العادية بفحص صلاحيات نطاق الوصول كاملاً ومراقبي القراءة؛ ويحفظ الخطأ أو توقف المراقب سجلات الخرج الضمنية وPC. تبقى معاملات الأجهزة غير مدعومة. تُنفّذ الحالات أيضاً على checked Unicorn، ويُعلن صراحةً عن تخطي النواقل الأصلية غير المتاحة.

يتيح `X64BitInstructions.def` تعليمات `BT/BTS/BTR/BTC` للسجلات وRAM العادية بعرض 16/32/64 بت. يُفسَّر فهرس السجل كقيمة موقَّعة بعرض المعامل ويختار كلمة كاملة؛ أما الفهرس الفوري فيبقى داخل الكلمة الأساسية. يحدث الاقتطاع إلى عرض العنوان قبل إضافة قاعدة FS/GS. يوفر المعالج CF والقيم المكتوبة، ويبقي `RAMTransaction` النتيجة خاصة حتى تقبلها دوال المراقبة. تُفحص الصلاحيات على النطاق الكامل، بما فيه الصفحات المخصصة منفصلًا والعناوين البديلة. يحافظ التوقف وفشل الاستدعاء الراجع ورفض الوصول على حالة CPU وRAM الأصلية. يقتصر LOCK على تعديل الذاكرة ذي المحاذاة الطبيعية؛ ولا يشمل الدعم MMIO أو SMP العتادي المتوازي. يقارن `X64BitStringTests.cpp` ترميزات مستقلة بالتنفيذ الفعلي على مضيف x64، ويفحص الفهارس السالبة واقتطاع العرض وعبور الصفحات والإلغاء وصيغ LOCK غير الصالحة. راجع [مرجع تعليمات Intel](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html).

يحدد `X64StringInstructions.def` تعليمات `MOVS/STOS/LODS` بعروض 8/16/32/64 بت على RAM العادية؛ ويغيّر `CLD/STD` علم الاتجاه وحده. يتحقق كل عنصر REP من كامل المعامل قبل المراقبة، ثم يثبت أثره عند حد يسمح بالاستئناف. يحافظ العطل اللاحق على العناصر المكتملة، بينما يترك الإيقاف أو استثناء المراقب العنصر الحالي دون تغيير. يضاف FS/GS إلى المصدر فقط بعد اختزال عرض العنوان. تحتفظ عمليات تحميل AL/AX بالبتات العليا، بينما يمدد EAX بالأصفار. تتطلب REP ذات العداد الصفري وعنونة 32 بت أن تكون بتات العداد العليا صفرًا، وكذلك بتات العناوين المشاركة في MOVS/STOS، لأن المعالجات الفعلية تختلف بخلاف ذلك. لا تزال REPNE مع MOVS/STOS/LODS ومعاملات الأجهزة لـ STOS/LODS غير مدعومة. يقارن `X64StringTransferTests.cpp` العروض والاتجاه والتداخل والعداد الصفري بتعليمات مضيف مستقلة، ويختبر الصلاحيات والأسماء البديلة والتفاف العنوان والأعطال والاستئناف. ينفذ برنامج تشغيل موارد WDK الأصلي عروض STOS/LODS الأربعة عبر `driver_resource_strings.def`.

يحدد `X64StringInstructions.def` أيضًا `CMPS/SCAS` على RAM العادية بعروض 8/16/32/64 بت مع `REPE/REPNE`. يتحقق كل عنصر من جميع القراءات قبل المراقبين، ويحدث أعلام الحساب الستة، وينتهي عند أول شرط توقف. يعيد عطل البيانات الأعلام إلى بداية REP المتصلة مع إبقاء تحديثات المؤشرات والعداد المكتملة؛ ويبدأ الاستئناف عبر الواجهة العامة من حالة CPU المنشورة. لا يغير الإيقاف أو استثناء المراقب العنصر الحالي، ولا تقرأ النهاية المبكرة العنصر التالي. يؤثر FS/GS في مصدر CMPS وحده، ويحافظ SCAS على المجمّع وسجل المصدر غير المستخدم. تبقى الأجهزة والبتات العليا الملتبسة عند عداد صفري بعرض 32 بت خارج النطاق. يقارن `X64StringComparisonTests.cpp` تعليمات المضيف المستقلة والأعلام والاتجاه والأسماء البديلة والتفاف العناوين والصلاحيات والاستئناف؛ ويلتقط اختبار إشارات Linux x64 السجلات عند العطل الحقيقي. ينفذ برنامج تشغيل WDK الأصلي شكلي التكرار الشرطي بكل العروض عبر `driver_resource_strings.def`. راجع [مرجع Intel](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html). يتحقق الاختبار الأصلي في Linux من الأخطاء قبل العنصر الأول وبعده، ويميّز بين استعادة flags الأولية على Intel والاحتفاظ بقيم آخر مقارنة المرصودة على AMD EPYC 7763 تحت Hyper-V ([الرصد الأصلي](https://github.com/NeverSight/NeverD/actions/runs/37202522130))؛ ويفشل صراحة عند مصنّع CPU غير معروف. تستعيد ضيوف checked قيم flags الأولية على جميع الخلفيات.

يفصل `WhpResourceCache.h` حالة وحدات CPU المنطقية عن أقسام WHP. تحتفظ بيئة التشغيل بقسم أصلي نشط واحد وتعيد استخدامه في الخطوات المتتالية لوحدة CPU نفسها. عند تبديل الوحدة، تحذف القسم السابق قبل إعادة إنشاء الخرائط والمعالج الافتراضي واستعادة الحالة الكاملة. تحتفظ الوحدات المنطقية بعروض `MemoryProjection` مستقلة وبذاكرة RAM المرجعية. يراعي الحصول على الحجز الإلغاء والموعد النهائي الحالي، ولا يؤدي حذف وحدة غير نشطة إلى حذف قسم وحدة أخرى. يحافظ x64 على مجموعة ميزات XSAVE الافتراضية للمضيف ويتحقق من إعدادات القسم الفعلية عبر `WHvGetPartitionProperty`، دون حذف الميزات التابعة لتقليص القناع. لا يوفر التبديل التعاوني بين الوحدات SMP عتادياً متوازياً.

يحتفظ `CheckedBackend` لكل CPU بمخزن لجلب التعليمات وسجل واحد من `cs_disasm_iter`. تعيد كل خطوة قراءة البايتات المسموح بتنفيذها وفك ترميزها؛ ولا تحتفظ بنتيجة فك ترميز قديمة بعد كتابة الكود أو تغيير العناوين البديلة أو استئناف التنفيذ. يرفض حق التنفيذ الحصري الدخول العودي قبل الوصول إلى التخزين المعاد استخدامه. يزيل ذلك تخصيص الذاكرة لكل تعليمة مع الحفاظ على المراقبة واعتراض خدمات النظام والمعالجة الدقيقة للأخطاء. تنتهي الخطوة الواحدة في نسخة Unicorn المثبّتة قبل جلب التعليمة التالية، بما يشمل البحث غير المباشر عن الترجمة، ولا تُحتسب إعادة محاولة كتابة الكود الداخلية تعليمةً مكتملة.

تدير `WhpX64Partition.h` إعادة استخدام سجلات x64 WHP داخل كل قسم فعلي. تستخدم الحزم الثابتة `WhpX64Registers.def` و`X64HostRegisters.def`؛ وتظل كل خطوة ناجحة تلتقط السجلات العامة والتحكم والمقاطع وحالة FP/SSE كاملة. لا يسمح بتجاوز المدخلات غير المتغيرة إلا خروج تصحيح مؤكد بالكامل. تتجاهل المقارنة البتات المحجوزة وحشو الاتحادات. تُثبّت تغييرات CR3 وCPL وTLS والسجلات العامة وFP؛ ويبطل الفشل الجزئي والإلغاء والاستثناء إعادة الاستخدام. يبدأ القسم الجديد بتثبيت كامل. يقلل ذلك النقل المتكرر دون توسيع التعليمات المقبولة أو ادعاء تسريع التنفيذ الكامل.

يلتقط WHP بيانات x87/SSE الوصفية من `WhpXsaveRegisters.def` مع السجلات العادية في استدعاء واحد إلى `WHvGetVirtualProcessorRegisters`. تبقى وحدة vCPU المتوقفة محمية بحجز القسم نفسه. يظل التقاط XSAVE الكامل وجميع فحوص الاتساق مطلوبًا قبل نشر الحالة. يُحذف استدعاء واحد لواجهة المضيف لكل خطوة، دون ادعاء تحسن مقاس في الإنتاجية.

يجيز `CheckedAArch64Instructions.def` و`AArch64InstructionEffects` في EL0/EL1 مجموعة محدودة من حساب FP32/FP64 الأساسي والمقارنة والنقل وSIMD ثابت العرض. يحفظ FPCR أنماط التقريب الأربعة وFZ وDN، ويحفظ FPSR الحالة المتراكمة وQC. تُرفض البتات غير المدعومة قبل التعديل. يفشل حساب FP16 وSVE/SME والاستثناء غير المقنّع والامتدادات الاختيارية والأشكال غير المدرجة صراحةً. لا يضيف ذلك تحميل برامج تشغيل Windows ARM64 أو بيئة نظام أخرى.

يمتلك `AArch64InstructionEffects` نطاقات RAM العددية وFP/SIMD الفردية والمزدوجة حتى 128 بت لكل معامل. يتحقق فضاء العناوين المشترك من كل صفحة قبل الدخول، ولا يثبت `RAMTransaction` إلا الكتابات الفيزيائية المعلنة كاملةً. يستقبل مراقب كتابة 128 بت كلمتين مرتبتين من 64 بت قبل الأثر. يحفظ التوقف والعطل RAM والمتجهات وتحديث العنوان. تساوي رقمي Xn/Vn مسموح؛ وتُرفض النطاقات المزدوجة التي تلتف عناوينها. يستخدم `NeverDAArch64MemoryTests` ترميزات مستقلة في `AArch64CrossPageCases.def` و`AArch64VectorMemoryCases.def`.

يستخدم KVM x64/ARM64 المتحكم `KvmRunControl` لتحضير الحالة والدخول إلى `KVM_RUN` وقراءتها على عامل vCPU خاص واحد. يحدث التحضير مرة واحدة حتى مع `EINTR`؛ يمنع الإلغاء وفشل القراءة نشر الحالة. ينفذ `KvmAArch64Machine.cpp` صيانة ترجمة العناوين ونقل الحالة العددية والمتجهية الكاملة بمهلة خطوة واحدة. ينشر المستدعي بعد تأكيد الانتهاء؛ ويبقى فك ISA ومعاملات RAM وسياسة النظام والمراقبون على خيط المستدعي. ما زال إثبات ARM64 الأصلي مطلوباً.

يقارن KVM السجلات العامة وحالة FP/SSE الكاملة بآخر حالة تصحيح جرى تأكيد قراءتها وفق `X64HostRegisters.def` و`X64FPState.def`، ويعيد تثبيت المدخلات المتغيرة. تدخل كتابات المضيف واستعادة السياق في المقارنة؛ وتبطل الاستثناءات والإلغاء والفشل إعادة الاستخدام. يظل إعداد الخطوة الواحدة وقراءة الحالة العامة/FP الفعلية قائمين لكل تعليمة.

على x64 يستعلم KVM عن `KVM_CAP_SYNC_REGS` ويستخدم مجموعتي `KVM_SYNC_X86_REGS` و`KVM_SYNC_X86_SREGS` المدعومتين بشكل مستقل. يعيد `KVM_RUN` المؤكد السجلات الفعلية عبر الذاكرة المشتركة، ما يتيح تجنب `KVM_GET_REGS` و`KVM_GET_SREGS` في الخطوات الناجحة المتتابعة. تبقى آلية ioctl للمجموعات غير المدعومة أو عند فشل الاستعلام الاختياري. تظل المدخلات المتغيرة مثبتة قبل `KVM_SET_GUEST_DEBUG` وتبقى بتات dirty المشتركة صفراً. تبطل الاستثناءات والإلغاء وفشل الالتقاط إعادة الاستخدام. يبقى التقاط FP/SSE الكامل إلزامياً، بينما تتجنب مدخلات FP غير المتغيرة إعادة ترميز XSAVE. يقلل ذلك استدعاءات نقل الحالة دون إثبات تسريع التنفيذ الكامل. [واجهة KVM](https://docs.kernel.org/virt/kvm/api.html#kvm-cap-sync-regs).

التنفيذ العتادي وحده لا يضمن زمناً إجمالياً أقل. يقوم التنفيذ الأصلي الحالي بفحص قبول التعليمة والمراقبة ونقل الحالة والخروج من VM لكل خطوة. قارن الصور والسيناريوهات الأصلية نفسها بميزانيات تعليمات وأحداث متطابقة، وأبلغ عن تطابق النتائج مع الأزمنة؛ وأدرج بدء CLI والتحميل عند قياس زمنه.

يستخدم Unicorn المتحقق منه `MachineRunControl`: يغطي سماح واحد صيانة ARM64 وتنفيذ الضيف والتقاط الحالة كاملةً. يتحقق `UC_HOOK_CODE` من رمز التوقف المستعار والمهلة عند دخول التعليمة. يحرر استدعاء المحرك المتزامن مرجع hook قبل العودة، لكن خطوة الآلة تحتفظ بالتحكم حتى النشر. يجمع Unicorn وWHP حالة CPU كاملةً بشكل خاص ويتحققان من التحكم نفسه قبل نشر خطوة ناجحة. ينشئ WHP السماح مرة واحدة قبل التحضير. يتقدم استثناء CPU x64 المؤكد على توقف يصل أثناء الالتقاط. تتخلى معاملة RAM المتحقق منها عن الكتابات المؤقتة عند إلغاء الالتقاط، ولا يتغير العقد البرمجي غير المقيد. يميز `MachineInterruptedError` الإلغاء المؤكد عن فشل المضيف أو الالتقاط. تعيد CPU المشتركة المتحقق منها `Stopped` أو `Deadline` وتحفظ CPU/RAM وتسمح بإعادة المحاولة؛ وتظل الأعطال الحقيقية `BackendFailure` حتى مع توقف متزامن.

يرفض `RunDeadline::invoke` دخول WHP المتوقف أو المنتهية مهلته قبل استدعاء المضيف، ويحفظ نتيجة المضيف الفعلية أثناء الإلغاء، ويؤكد انتهاء استدعاءات المقاطعة قبل تحرير رمز التوقف المستعار. يتحقق KVM وWHP من الحالة الخاصة المقروءة بالكامل على خيط الاستدعاء المالك لحق التنفيذ قبل تصنيف توقف أو انتهاء مهلة متزامن. تحتفظ أخطاء المضيف أو قراءة الحالة الفعلية واستثناءات CPU x64 الموثقة بالأولوية. تبقى الحالة الناجحة العادية خاصة حتى تنتهي فحوص الإلغاء؛ وتتخلص المقاطعة المؤكدة من آثار CPU/RAM التخمينية وتسمح بإعادة المحاولة. يشترك التحضير والتنفيذ الأصلي وقراءة الحالة في سماح واحد لكل خطوة. هذا التحكم تعاوني ولا يضمن حدًا صارمًا للوقت الفعلي.

## macOS HVF

`hvf` · Hypervisor.framework · Apple Silicon → ARM64 · Intel Mac → x86-64.

[Setup, signing and native hardware validation (English)](../macos-hvf.md)

يدعم ARM64 checked تعليمات `LDXR/STXR` بعرض 8/16/32/64 بت، وأزواج `LDXP/STXP` بعرض 32/64 بت، وصيغ acquire/release و`CLREX`. تشترك KVM وWHP وUnicorn checked في مراقب على مستوى ISA يتتبع حجوزات مادية بحجم 16 بايت؛ ولا تمنع مخارج التنفيذ خطوة بخطوة تقدّم الحلقات. تُبطل الكتابات المعتمدة الحجز حتى إن بقيت البايتات كما هي، بما يشمل الأسماء البديلة والعروض المحتفظ بها. يحفظ الإيقاف الحالة غير المنشورة، ولا تلغي اللقطات الكتابات اللاحقة. تتبع العمليات الحصرية checked قواعد FEAT_LSE2: يُسمح بالمعامل غير المحاذى داخل كتلة محاذاة بحجم 16 بايت، ويؤدي عبور حدودها إلى `alignment`. تُطابق الكتابات ذات العرض نفسه وحدة الحجز المادية. تُفحص المحاذاة والصلاحيات قبل تقرير نجاح التخزين المشروط حتى عند انتهاء الحجز. لا يشمل هذا الملف MMIO أو تعليمات LSE الذرية الاختيارية أو SMP المتوازي. يستخدم Unicorn ARM64 هذا المراقب أيضًا ضمن عقد `Software`، بما في ذلك مشاركة RAM المادية بين وحدات CPU البرمجية ووحدات checked. يحتفظ عقد `Software` في Unicorn بنموذج المحاذاة الطبيعية للمحرك.
