# Эмуляция гостевых процессов

`neverd emulate` запускает образ с явно заданным профилем гостевой ОС. CPU-транспорт, разбор образа, вход в процесс и службы ОС имеют отдельные границы ответственности. Включите `NEVERD_ENABLE_CPU_EMULATION=ON`; эмуляция драйверов также включает CPU.

Первый профиль `linux-elf64-v1` запускает ELF `ET_EXEC` для x64/AArch64 и саморелокирующие статические PIE `ET_DYN` на CPL3 или EL0. Он загружает реальные сегменты ELF, строит начальный стек, возобновляет выполнение квантами и обрабатывает явные запросы системных вызовов Linux. Это самостоятельная модель процесса, а не полная дистрибуция Linux и не обещание запуска произвольных бинарников libc. Динамическая линковка, сигналы, потоки, файловые системы и неподдерживаемые службы явно приводят к ошибке. Ограниченный x64-профиль допускает некоторые формы SSE/SSE2; AArch64 остаётся только целочисленным. Windows, Android, Darwin и другие нагрузки ядра рассматриваются отдельно.

## CLI и SDK

```bash
neverd emulate guest.elf --profile=linux-elf64-v1 \
  --options='{"backend":"auto","arguments":["guest","argument"],"environment":["MODE=test"],"instruction_limit":100000}'
```

Совместимый Linux-хост выбирает KVM, Windows-хост — WHP; другие сочетания ISA хоста/гостя используют Unicorn. Недоступный выбранный бэкенд приводит к ошибке без скрытой подмены. Даже на Windows ELF выполняется в модели Linux-процесса. Перечень инструкций и ограничения описаны в разделе [выполнение CPU](cpu-execution.md).

CLI выдаёт один JSON-отчёт. Код 0 означает нулевой статус гостя, 2 — иной статус, 3 — неполное выполнение (включая сбои и лимиты), 1 — неверная настройка/API. Реальный статус гостя находится в `exit_status`. Добавленная точка C [`neverd_emulate_process_json`](../../include/neverd/sdk/NeverDCAPIProcess.h) принимает сессию, непустой путь, явный профиль и необязательный JSON параметров. Результат освобождается через `neverd_free_string`; NULL означает ошибку настройки, подробности — `neverd_last_error`. Сбой гостя или остановка по ресурсам всё равно возвращают отчёт. Загруженный образ анализа не требуется и не изменяется.

```python
report = session.emulate_process(
    "guest.elf", "linux-elf64-v1",
    '{"backend":"unicorn","arguments":["guest"],"environment":[]}',
)
output = bytes.fromhex(report["stdout_hex"])
```

## Параметры и результаты

Параметры — JSON-объект размером до 64 KiB. Неизвестные/null-поля, неверные типы, встроенный NUL и неположительные лимиты отклоняются.

| Параметр | По умолчанию | Контракт |
|---|---|---|
| `backend` | `auto` | `auto`, `unicorn`, `kvm` или `whp` |
| `arguments` | Имя файла | Полный argv, включая argv[0]; пустой список выбирает значение по умолчанию |
| `environment` | `[]` | Явные строки гостя; окружение хоста не наследуется |
| `instruction_limit` | 100000 | Общее число допущенных попыток инструкций |
| `event_limit` | 10000 | События syscall, учитываемые до обработки службы |
| `timeout_microseconds` | 5000000 | Монотонный deadline после настройки процесса |
| `memory_limit` | 67108864 | Бюджет физической/отображённой памяти |
| `stack_size` | 1048576 | Стек с выравниванием по странице в рамках бюджета |
| `output_limit` | 1048576 | Общий объём stdout/stderr в байтах |
| `instruction_quantum` | 1024 | Интервал допуска до возврата runtime |

`schema_version` равен 1. Отчёт содержит профиль, архитектуру, выбранный бэкенд и причину, `stop_reason`, nullable `exit_status`, диагностику, входной/текущий PC, счётчики, записи служб и последний типизированный выход CPU. Адреса, syscall-номера, регистры аргументов и биты возврата — hex-строки **без** `0x`; `stdout_hex`/`stderr_hex` сохраняют NUL и некорректный UTF-8. Результат syscall null означает отсутствие моделируемого возврата (например, exit или неподдерживаемый запрос), а не успешный ноль.

## Семантика профиля Linux

Политика ОС использует декодированные заголовки программ существующего ELF-загрузчика. Она проверяет ABI-теги, выравнивание сегментов, отображённые таблицы заголовков и границы пользовательских адресов. План отображения проверяет диапазоны, права, пересечения и бюджет до выделения памяти и публикует только полностью подготовленное частное адресное пространство. Сохраняются префиксы/хвосты файловых страниц, BSS обнуляется, права сегментов соблюдаются, для стека резервируются защитные промежутки. Пересекающиеся страницы и противоречивые заголовки отклоняются, а не угадываются.

Статический PIE использует детерминированный load bias не ниже `0x40000000`, увеличивая его для большего выравнивания `PT_LOAD`. Сегменты, PC входа и `AT_PHDR`/`AT_ENTRY` используют один bias; исходные program-header значения не меняются, а без интерпретатора `AT_BASE` равен нулю. Отображаются исходные байты файла, без analysis-fixup; релокацию и инициализацию выполняет сам гость. Загрузчик декодирует `PT_DYNAMIC` из ограниченных записей исходного файла без зависимости от section headers. Если таблица есть, она должна быть читаемой, завершённой и содержать не более 4096 записей. `PT_INTERP` и внешние теги зависимостей/filter/audit отклоняются; dynamic linker, разрешение символов и конструкторы не предоставляются.

Начальный стек содержит выровненные argc/argv/envp/auxv, PHDR/PHENT/PHNUM, entry, размер страницы и идентификаторы. Моделируемые PID/TID/UID/GID равны 1000. Для воспроизводимости `AT_RANDOM` содержит первые 16 байт SHA-256 входа; это детерминированная политика модели, не криптографическая энтропия. HWCAP/HWCAP2 равны нулю; vDSO отсутствует.

Реализованы `write`, `exit`, `exit_group`, `getpid` и `gettid`, `mmap`, `mprotect`, `munmap`, `brk` с отдельными номерами для [x64](https://github.com/torvalds/linux/blob/master/arch/x86/entry/syscalls/syscall_64.tbl) и [ARM64](https://github.com/torvalds/linux/blob/master/include/uapi/asm-generic/unistd.h). Возврат x64 SYSCALL применяет clobber RCX/R11, RAX и следующий PC. ARM64 использует x8 для номера, x0 для результата. Неизвестные вызовы останавливаются с `unsupported_service`; системные вызовы хоста не выполняются.

Статические TLS-шаблоны `PT_TLS` проверяются как факты загрузчика: один шаблон, ограниченные файловые/памятные диапазоны, согласованное выравнивание и читаемые инициализированные байты. Старт гостя выделяет и инициализирует TLS-блоки и устанавливает указатель потока; модель Linux не выдумывает libc-специфичный TCB/DTV. Это поддерживает compiler-generated local-exec TLS во freestanding-программах. Динамический TLS и потоки ОС вне объёма.

На x64 `arch_prctl` поддерживает `ARCH_SET_FS`, `ARCH_GET_FS`, `ARCH_SET_GS`, `ARCH_GET_GS`. Set принимает user-range base даже без отображения; последующие разыменования всё равно проверяют права. Kernel-range base возвращает гостевой `EPERM`, неверный Get destination — `EFAULT` без CPU fault. Другие операции явно завершаются ошибкой. ARM64 startup устанавливает `TPIDR_EL0` через `MSR`; `MRS`, обращения FS/GS и восстановление контекста сохраняют указатель потока между квантами и входами backend. Это не реализует планировщик.

Дескрипторы 1 и 2 — виртуальные приёмники байтов. `write` проверяет читаемые пользовательские страницы; если следующая страница недоступна, возвращает читаемый префикс, а если не читается ни байта — `EFAULT`. Неверный дескриптор даёт `EBADF`; запись нуля байтов на допустимый дескриптор не читает указатель. Атомарность Linux pipe и файлы не моделируются. Превышающая лимит вывода запись останавливается до публикации.

Анонимная память использует то же адресное пространство процесса и физический бюджет, что образ и стек. `mmap` принимает только `MAP_PRIVATE | MAP_ANONYMOUS` с обычными `PROT_NONE`, `PROT_READ`, `PROT_READ | PROT_WRITE`, `PROT_READ | PROT_EXEC` или читаемым RWX. Свободная выровненная подсказка учитывается; иначе поиск промежутков начинается с `0x100000000`, затем с минимального пользовательского адреса, сохраняя защитные области стека. Это детерминированное размещение, не Linux ASLR. Новые страницы независимы и обнулены; частичное снятие отображения может освободить незакреплённые страницы. Проекция CPU или удерживаемое представление backing может продлить жизнь удалённого выделения до конца своей жизни.

Длины округляются до страниц. `munmap` допускает пробелы и повторное удаление; `mprotect` меняет отображённый префикс, затем возвращает `ENOMEM` на пробеле. `PROT_NONE` сохраняет выделение и байты, запрещая гостевой доступ. Сырой `brk` возвращает запрошенную байтовую границу при успехе и прежнюю при отказе, а не ноль/минус один обёртки libc. Начальная граница — выровненный конец образа. Рост учитывает другие отображения и бюджет; сокращение сохраняет байты оставшейся частичной страницы. Правила и приоритеты ошибок следуют Linux [mapping](https://github.com/torvalds/linux/blob/v6.8/mm/mmap.c) и [protection](https://github.com/torvalds/linux/blob/v6.8/mm/mprotect.c).

Файловые, совместные и фиксированные отображения, рост вниз, огромные страницы, блокировка памяти, ключи защиты, режимы только исполнения/записи и другие флаги явно не поддерживаются: остановка до публикации эффектов или выдуманного возврата. Обычные ошибки диапазона, длины и выравнивания в допустимом подмножестве возвращают гостевую ошибку и разрешают продолжение. Гостевые указатели и запросы отображения не передаются ОС хоста.

## Проверка

```bash
cmake --build build-cpu --target NeverDLinuxProcessTests NeverDExecutionSessionTests NeverDX64MemoryUpdateTests NeverDThreadPointerTests --parallel 4
ctest --test-dir build-cpu -L '^NeverD(LinuxProcess|ExecutionSession|X64MemoryUpdate|ThreadPointer)Tests$' --output-on-failure
# Для сборки shared-library/CLI:
cmake --build build-cpu --target NeverDProcessPublicTests --parallel 4
ctest --test-dir build-cpu -L '^NeverDProcessPublicTests$' --output-on-failure
```

Тесты компилируют автономные входы ELF на ассемблере и C для обеих ISA: data/BSS, реальные стартовые данные, ошибки syscall, двоичный вывод, права, частичные записи, неподдерживаемые службы и бюджеты между квантами. TLS инициализирует независимые выровненные блоки, BSS и указатели потока и проверяет их сохранение; x64 проверяет ошибки `arch_prctl` без потери прежней базы. Недоступные backend явно пропускаются. Публичный набор проходит общую C ABI и CLI, сверяя отчёты и коды выхода. PIE проверяет auxv и исходно нулевые RELA-слоты до собственных перемещений данных и функций. Тесты отображения сохраняют fixup при выборе аналитического источника байтов; динамические таблицы проверяются без секций и с неверными/зависимыми входами. Обе ISA проверяют выделение, защиту, пробелы, повторное отображение, рост/сокращение кучи и обработанные ошибки. Настоящие гостевые записи проверяют сбои после обычной и частичной смены защиты. x64 переписывает код по одному адресу между RW и RX и вызывает обе версии; тот же ELF нативно запускается в Linux как независимый оракул результатов и сбоев. Тесты памяти проверяют исчерпание бюджета, освобождение и авторитетные снимки отображений без удержания RAM. Кросс-компиляция и Unicorn ARM64 не доказывают работу нативного ARM64 KVM/WHP.
