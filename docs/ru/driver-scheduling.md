# Вытесняющее планирование драйверов Windows

Необязательный объект `scheduling` включает детерминированное вытеснение на CPU0 для драйверов Windows x64 с Unicorn, KVM или WHP. Без него сохраняются кооперативное планирование и продвижение виртуального времени только при простое. Оба поля — положительные целые, произведение должно помещаться в `uint64_t`. Пустой объект выбирает значения ниже.

```json
{
  "scheduling": {
    "quantum_instructions": 1024,
    "instruction_time_100ns": 1
  }
}
```

`quantum_instructions` ограничивает число допущенных попыток машинных инструкций потока. `instruction_time_100ns` задаёт виртуальное время на попытку, а не скорость оборудования. API модели и транзакции инструкций завершаются до переключения. Граница события не обнуляет остаток кванта. Политика сохраняется в `configuration.scheduling`.

Готовые продолжения, новые рабочие задачи и системные потоки используют общий порядок готовности. Вложенные вызовы и SEH разделяют квант своего потока. Переключение сохраняет полный контекст CPU, идентичность потока, состояние APC, эффективный IRQL и отображения процесса. PASSIVE/APC допускает вытеснение; DISPATCH и выше блокируют переключение потоков. Критические и защищённые области отключают APC, но не вытеснение.

Инструкции продвигают таймеры и DMA по хронологическим срокам. Отмена ждёт доступности cancel-lock и, для WDM, возврата dispatch. Выгружаемые завершения provider, политика питания и PoFx ждут границы PASSIVE; исходные сроки сохраняются, наблюдения фиксируют фактическое время обслуживания. Независимые callbacks часов отделены по владению от блокирующих PoFx callbacks исходного потока. Результат ожидания фиксируется в его срок, до последующего сброса таймера или сигнала события, даже если одна попытка инструкции пересекает оба срока.

Классы и динамическое повышение приоритетов Windows, параллельные CPU модели ОС, произвольная вложенность прерываний, доставка APC и потоки Windows ring3 не реализованы. Параллельное исполнение CPU — отдельная возможность. Оригинальные скомпилированные драйверы проверяют короткие кванты, состояние floating point/GS, ожидания по времени, чередование подключений к процессам, отмену и продолжения PoFx. Нативные доказательства для ARM64 отслеживаются отдельно.
